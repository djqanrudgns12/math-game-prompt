## 2. 킹수학에서 얻은 제품 설계 근거

### 현재 화면

킹수학 배틀에는 1~6인 개인전과 여러 팀전 설정, 연산·분수·빈칸·규칙 등 문제 분류, 받아올림 여부를 구분하는 수준 선택이 있다. 플레이 화면에서는 학생별 세로 영역과 개별 숫자 키패드를 사용한다. 이는 인원과 수학적 조건을 별도 축으로 두는 참고 사례다. [킹수학 배틀](https://kingsmath.com/kingmath/)

메이킹에서는 같은 문제 세트를 퀴즈 배틀, 월드컵 축구, 짝찾기 캐치, 잇기, 슈팅 배틀, 스피드 터치로 사용하는 설명을 확인했다. 화면 제목 일부는 ‘다섯 가지’였으나 실제 설명 카드는 6개였다. 문제·정답·오답을 별도로 입력하고 표를 붙여넣는 흐름이 있다. [킹수학 메이킹](https://kingsmath.com/make0901/)

설계 시사점: **문제 데이터와 게임 규칙을 분리하면 같은 학습 내용을 여러 게임으로 표현할 수 있다.** 이 제품은 여기에 ‘활동지의 풀이 원리를 추출하여 변형 문제 생성 코드를 만드는 과정’을 더한다.

## 3. GitHub·Reddit에서 보완한 점

## 4. 구조화된 프롬프트 설계 방향

OpenAI 문서는 명확한 목표·제약·성공 기준·출력 형태와 구분자를 권장한다. 추론 과정을 길게 출력하도록 강요하는 방식 대신 결과물의 계약을 구체화한다. 이는 설계 참고이며 무료 ChatGPT에서 동일한 성공률을 보장하는 근거는 아니다. [추론 모델 프롬프트 원칙](https://developers.openai.com/api/docs/guides/reasoning-best-practices), [목표와 성공 기준 중심의 지침](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.5)

권장 생성 구조:

`공통 제작 계약 + 선택한 게임 규칙 1개 + 선택한 디자인 1개 + 학습·난이도 조건 + 참여·터치 조건 + 자료 해석 정책 + 검증·출력 계약`

20개 장르 전체의 제작 지침을 매번 붙이지 않는다. 생성기 안에는 전체 카탈로그가 있어도 복사하는 프롬프트에는 선택한 항목만 넣는다. 한 번에 제작할 결과물도 선택한 게임 하나다. 최초 12개 제안에서 사용자 인터뷰로 20개로 확대되었다.

자료에서 읽은 문항 → 학습 개념·풀이 원리·변수·제약 추출 → 생성 함수와 독립 검증 규칙 작성 → HTML 실행 시 새 문항 생성의 흐름을 사용한다. HTML 실행 중에 문서를 읽거나 LLM을 호출하는 것으로 설명하지 않는다.

## 5. 전자칠판 구현 근거와 제안 수치

Pointer Events는 마우스·펜·터치 입력을 다루며 포인터별 식별·캡처·취소 처리 수단을 제공한다. ‘브라우저가 Pointer Events를 지원한다’와 ‘전자칠판에서 6명의 접촉을 실제로 구분해 전달한다’는 별도 검증 대상이다. [MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)

W3C의 강화된 타깃 크기 기준은 예외 조건과 함께 44×44 CSS px를 제시한다. 이 값이 전자칠판 아동용 최적 크기라는 의미는 아니다. 본 제품은 주요 답 버튼 64 CSS px 이상을 초기 목표로 삼고 큰 화면에서 확대하며, 실제 보드의 크기·배율·설치 높이로 조정하는 방안을 제안한다. [W3C Target Size Enhanced](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)

전자칠판의 학생 조작은 아래쪽에 모으고 교사가 조작대 높이를 조절할 수 있게 한다. 6인 화면을 단순한 2행×3열로 나누면 윗줄 학생의 도달 높이가 문제가 될 수 있다. 가로로 배치한 학생별 조작대와 그 위의 표시 영역을 우선 후보로 둔다. 이 배치는 아직 물리 기기 검증 전이다.

## 6. 남은 검증

- 실제 무료 ChatGPT에서 활동지 이미지·PDF를 읽고 완결 HTML을 만드는지, 최초 성공과 수정 후 성공을 나누어 측정.
- 물리 전자칠판에서 1·2·3·4·5·6명 동시 터치, 드래그, 손바닥 접촉, 영역 경계, 전체화면 전환 검증.
- 학년별 교사의 문항·정답·난이도 검토와 학생 도달 높이·뒷자리 가독성 확인.
- 모든 장르를 단순 객관식으로 바꾸지 않고도 활동지 학습 목표를 유지하는지 점검.
- 생성된 프롬프트와 결과물의 품질은 대표 자료를 정한 뒤 실험해야 하며 이번 조사만으로 인증하지 않음.
