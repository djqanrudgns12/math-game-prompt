# 수학 공작소 PRD

2026-09-11 보완: 프롬프트 계약 1.3을 최신 출력 사양으로 적용한다. 효과음 기본값은 켬(사용자 시작 동작 후), 움직임은 기기 설정 따름이다. 생성기에서 두 값을 선택할 수 있고 무음 선택도 효과음 구현 자체를 생략하지 않는다. 아래 이전 기본값과 충돌하면 이 보완을 우선한다.

정답·오답·단계 달성·종료별 시청각 반응을 필수로 구현하고 6인 반응 시 소리 합치기·동시 음원 제한·효과 레이어 터치 통과·일시정지 정리를 적용한다. 학생 화면은 목표·시간·진행 하나와 현재 문제·응답에 집중하고 자료 분석·검사·설정 설명은 교사 메뉴에 둔다. 문제는 자료에 맞는 2~4개 변형을 같은 조작 흐름에서 사용하며 원시 조건을 다시 푸는 독립 검산, 의미상 중복 제거, 유형별 난도·경계 검사, 교사 ‘문제 점검’을 구현한다. 적합한 변형 수가 적은 자료는 개수를 억지로 맞추지 않는다.

버전: 2.2 / 상태: 조립기·6인 입력 참조·디자인 시제품 자체 시험 반영, 무료 생성·물리 보드 검증 전 / 작성일: 2026-09-10

이 문서는 현재 요구사항의 기준이다. 상세 조립 구조는 [생성기 설계](generator-architecture.md), 출력 본문은 [프롬프트 계약](prompt-contract-draft.md)을 따른다. 이전 버전의 숫자·분수 키패드와 학년 표시 전제는 폐기했다. 기존 활동지 분석은 시험 사례이며 지원 범위를 한정하지 않는다.

## 1. 제품 정의

초등 교사가 수업 조건을 선택하면, 활동지와 함께 ChatGPT에 붙여넣어 전자칠판용 수학 게임 HTML을 만들 수 있는 구조화된 프롬프트를 생성한다. 생성기 자체는 LLM을 호출하지 않는 단일 HTML 파일이다. 생성 결과로 만드는 게임도 단일 HTML 파일이다.

## 2. 사용자에게 확인한 사항

| 항목 | 확정 내용 |
|---|---|
| 교사 숙련도 | 초보자·시니어 중심. 프롬프트 복사·붙여넣기 수준을 기준으로 설명 |
| ChatGPT 이용 | 무료 이용자 중심. 유료 기능을 필수로 삼지 않음 |
| 연수 시간 | 현재 제품 범위를 결정하는 제약으로 사용하지 않음 |
| 학년 | 전 학년 지원, 주 사용은 3~6학년 예상 |
| 자료 | 교사별 서로 다른 사진·PDF 활동지 1~2개를 ChatGPT에 첨부. 학년·단원·차시 표시가 없어도 문제 내용에서 학습 목표 분석 |
| 참여 | 1~6명 모두 동시 조작을 선택할 수 있어야 함 |
| 형태 | 생성기와 생성 게임 모두 단일 HTML |
| AI 연결 | 생성기 안에 LLM/API 연결 없음 |
| 제작 진행 | 자료가 명확하면 바로 HTML 제작. 모호한 부분만 질문 |
| 문항 변형 | 원본의 긴 문장제를 적극 재구성하여 단순 연산·가벼운 문장제 등으로 변형 |
| 장르 수 | 고정 후보 20개. 겹치지 않는 핵심 행동·게임 진행으로 구분 |
| 장르 확장 | 20개 선택 + 자료에 맞는 새 게임 구상 + 직접 아이디어 입력 |
| 완성 게임 설정 | 인원·시간·난이도·소리·조작 높이를 게임 안에서 변경 |
| 자료 형태 | 사진·PDF 혼용. 특정 쪽·문항만 사용하기도 함 |
| 문제 진행 | 장르·게임 형태에 맞게 설계자가 결정. 교사에게 추가 필수 선택으로 요구하지 않음 |
| 수업 분위기 | 게임에 맞게 개인 대결·팀 대결·협동을 추천하고 교사가 변경 |
| 실제 환경 | Windows PC에 연결된 전자칠판. 화면 복제와 확장 모두 지원 |
| 학생 응답 | 주관식·숫자/분수 키패드·글쓰기·필기 인식 금지. 선택·잇기·분류·순서·제한된 조각 구성 등 손동작 |
| 조작 위치 | 모든 학생 조작의 시작점·도착점·확정·도움·취소가 하단 도달 영역 안에 있음. 상단은 관람 영역 |
| 재미 | 수학 판단이 성과의 핵심. 정밀 조준·빠른 반사·복잡한 컨트롤이 필수인 게임 제외 |
| 모션 의미 | 전자칠판 터치·끌기·잇기. 카메라 신체 인식 기능은 포함하지 않음 |

사용자 요구는 위 표로 확정했다. 구체적인 장르 규칙·기본값·화면 치수는 설계안으로 채택하고 시범 결과에 따라 조정한다. 현재 프롬프트 조립기와 디자인 시제품, 공통 입력 검증실을 구현했다. 출시용 생성기 전체와 20종 생성 게임·무료 ChatGPT 성능·물리 보드의 검증이 완료된 상태는 아니다.

## 3. 성공하는 사용자 경험

1. 교사가 생성기 HTML을 연다.
2. 수업·게임·디자인 조건을 고른다. 기본값만 사용해도 프롬프트가 완성된다.
3. ‘프롬프트 복사’를 누른다.
4. ChatGPT 새 대화에 프롬프트를 붙이고 활동지 1~2개를 첨부한다.
5. 자료가 명확하면 바로 제작한다. 첨부 누락·판독 불가·핵심 개념 충돌 등만 질문한다.
6. 완성된 HTML을 내려받거나 코드 전체를 HTML로 저장한다.
7. 교사 검토와 터치 확인을 거쳐 학생이 게임한다.
8. 같은 조건으로 다시 하거나 수업 조건을 바꾼다. 문제 오류·화면 오류는 준비된 수정 요청으로 해결한다.

생성기에서 첨부를 요구하는 가짜 업로드 UI를 만들지 않는다. 첨부 대상은 ChatGPT이며, 생성기는 실제 첨부 여부를 알 수 없다. 프롬프트에는 첨부가 없으면 게임 제작 전에 자료를 요청하도록 넣는다.

## 4. 선택 항목 제안

초보 화면에는 필수 선택만 보이고 나머지는 ‘더 설정하기’에 둔다.

| 구분 | 항목 | 제안 값·행동 |
|---|---|---|
| 상세 | 학년 | 지정 안 함(자료 수준 유지, 추천)·1~6학년. 미표기 학년을 정확히 알아야 제작할 수 있는 구조 금지 |
| 기본 | 게임 유형 | 아래 20개 후보 또는 ‘자료에 맞는 새 게임 구상’. 직접 아이디어 입력 추가 |
| 기본 | 디자인 | 아래 12개 후보 중 하나 |
| 기본 | 수학 난이도 | 하·중·상. 첨부 자료 기준으로 정의 |
| 기본 | 플레이 시간 | 45·60·90·120초, 선택적으로 무제한 |
| 기본 | 동시 참여 인원 | 1~6명 |
| 기본 | 수업 목표 한 줄 | 선택 입력. 예: 같은 분모 분수 크기 비교 |
| 상세 | 진행 성격 | 개인 도전·개인 경쟁·팀 경쟁·공동 목표 |
| 상세 | 진행 템포 | 여유롭게·보통. 수학 난이도와 독립. 정밀 조작·반사 속도를 난이도로 삼지 않음 |
| 상세 | 학생 행동 선호 | 게임에 맞게 추천·답/식 고르기·잇기·분류·순서·조각 구성. 임의 수치 작성 옵션 없음 |
| 상세 | 자료 범위 | 쪽·문항 번호·제외할 문제를 자연어로 입력 |
| 상세 | 변형 범위 | 원본을 적극 게임화. 연산·가벼운 문장제·조작 과제로 변환하되 학습 목표 유지 |
| 안내 | 문제 배분 | 장르에 따라 자동 결정. 필요하면 고급 설정에서 지원 가능한 대안만 노출 |
| 상세 | 오답 처리 | 단서 후 다시·짧은 설명 후 다음. 연타 보상 없음, 탈락 없음, 한 학생 오답에 전체 정지 없음 |
| 상세 | 생각할 시간 | 문항 제시 후 입력 잠깐 잠금 여부. 암산 속도만 평가하지 않는 옵션 |
| 상세 | 교사·접근성 | 조작대 높이·큰 글자·소리·움직임 줄이기 |

초기 기본값: 학년 지정 안 함, 퀴즈, 챌린지 스타디움, 수학 난이도 중, 60초, 2인, 수업 방식은 게임 추천, 진행 템포 보통, 단서 후 다시, 소리 끔, 낮은 조작대. 장르 미리보기에 수업 방식 추천을 함께 표시한다. 기본값은 자료의 학습 범위를 대신하지 않는다.

## 5. 게임 유형 20개 후보

이 목록은 조사에서 얻은 패턴과 신규 설계 제안이다. 킹수학의 공식 분류가 아니다. 모든 후보는 1~6명이 각자 동시에 조작하는 버전을 명세해야 하며, 1인에서는 목표 기록 또는 개인 목표로 동작한다. 실제 인터페이스에는 쉬운 이름과 한 문장 행동 설명을 사용한다.

| ID | 교사용 이름 | 수학과 게임의 연결 | 1~6인 구현 방향 |
|---|---|---|---|
| quiz | 퀴즈 | 고정된 답·식·그림 중 수학적으로 맞는 것을 선택 | 독립 문제·답 영역 |
| race | 레이싱 | 문제로 얻은 이동량과 갈림길 선택으로 도착 순서 경쟁 | 공통 경주장 + 개인 조작대 |
| tug | 줄다리기 | 해결한 값·힘의 배분이 서로 상쇄되며 중앙 표시 이동 | 개인 입력을 팀별 합산, 홀수 인원 균형 규칙 필요 |
| boss | 보스전 | 공격·보호 역할을 선택하고 함께 단계별 공동 목표 달성 | 개인 입력 + 공통 보스, 1인에서는 역할 전환 |
| defense | 디펜스 | 얻은 수학 자원으로 방어 위치를 정해 다가오는 적 방어 | 개인 방어 구역, 동시 입력 |
| target | 슈팅 | 여러 표적의 수학 조건을 판단해 하단 표적 카드를 선택, 자동 발사 | 정밀 조준·움직이는 표적 직접 터치 없음 |
| bingo | 빙고 | 답에 해당하는 칸을 선택해 줄 완성 | 개인 미니 보드와 도달 가능한 조작대 |
| match | 선 잇기 | 모두 보이는 식·값·표현·도형의 관계 연결 | 개인 카드판, 두 번 탭 또는 드래그 |
| memory | 카드 뒤집기 | 숨겨진 카드 위치를 기억해 수학적 관계가 맞는 카드 찾기 | 개인 뒤집기 보드, 각자 독립 진행 |
| sort | 분류 게임 | 조건에 따라 수·식·도형을 분류 | 개인 분류 버튼·칸 |
| path | 미로 | 통과 가능한 수학 조건과 길의 연결을 함께 판단해 출구 찾기 | 개인 미로, 이동 버튼 또는 칸 탭 |
| sequence | 순서 퍼즐 | 수·식·도형을 순서대로 구성 | 개인 슬롯, 탭 선택·배치 |
| build | 조립 퍼즐 | 조각을 분할·회전·배치해 목표 도형 또는 양 구성 | 자료에 맞는 조작 하나만 선택, 개인 작업 영역 |
| merge | 블록 합치기 | 결합 가능한 타일을 골라 새 값으로 합치고 목표 만들기 | 개인 작은 보드, 연쇄 합성 규칙 명시 |
| territory | 영역 점령 | 수학 과제로 얻은 권한과 인접 조건에 따라 칸 선택·확장 | 공동 지도 + 개인 선택대, 같은 칸 충돌 규칙 명시 |
| balance | 저울 퍼즐 | 양쪽 값을 조정해 등식·등량 성립시키기 | 개인 저울, 더하기·빼기 조작 |
| estimate | 어림 과녁 | 목표값이 놓일 눈금 구간·근삿값 카드를 골라 불확실한 범위를 좁힘 | 하단의 이산 구간 선택, 손가락 위치 오차 채점 없음 |
| rhythm | 패턴 퍼즐 | 반복·변화 규칙에 맞는 다음 블록을 골라 패턴을 연장하고 완성 후 재생 | 리듬은 결과 연출, 정해진 박자에 누르는 시험 없음 |
| resource | 상점 경영 | 예산·재고 안에서 물건과 수량을 선택해 주문 조건 충족 | 개인 상점, 정수 단위로 가격·잔액 계산 |
| code | 추리 퍼즐 | 수학적 단서를 하나씩 적용해 후보를 제거하고 비밀값 찾기 | 개인 후보판·단서, 유일한 해 검증 |

중복 방지 기준: 같은 문제·같은 버튼·같은 보상에 배경만 바꾸면 새로운 유형으로 세지 않는다. 선 잇기는 공개된 관계, 카드 뒤집기는 숨긴 위치를 다룬다. 순서 퍼즐은 주어진 유한 집합 재배열, 패턴 퍼즐은 다음 항·블록 생성이다. 경주는 경로 비용 선택, 영토는 인접한 공간 확장이다. 패턴 퍼즐의 내부 ID rhythm은 호환성을 위해 유지한다. 장르별 필수 행동과 끝 조건은 생성기 설계의 카탈로그 계약으로 관리한다.

새 장르 확장은 정적 생성기에서 장르를 ‘발명했다’고 표시하지 않는다. ChatGPT가 첨부 자료와 선택 조건을 바탕으로 구상하는 별도 경로다. 20개 고정 목록 외에 ‘자료에 맞는 새 게임 구상’을 제공하고 직접 아이디어 입력도 지원한다. 직접 아이디어는 고정 장르의 세부 요청 또는 새 게임의 구상 조건으로 사용한다. 핵심 규칙 하나와 보조 규칙 하나 이내로 제한하는 방안을 제안한다. 과도한 복합 장르는 무료 환경에서 제작·수정 부담을 키울 수 있으므로 별도로 품질을 검증한다.

규칙 공백을 남기지 않는다. 각 게임 명세에는 시작 상태, 한 문항의 입력·판정·보상, 오답, 승패·동점, 종료, 재시작을 포함한다. 빙고에서 답 중복, 팀전에서 홀수 인원, 짝맞추기에서 동치값 다중 연결은 별도의 규칙이 필요하다.

모든 활동지가 모든 유형과 자연스럽게 맞는 것은 아니다. 생성기는 LLM이 없으므로 첨부 자료와의 적합성을 판정했다고 표시할 수 없다. 자료를 읽은 ChatGPT가 선택 장르를 유지하면서 입력을 맞추고, 학습 목표를 훼손하는 경우 최소 수정안을 알려주는 정책을 둔다.

| 추리 퍼즐 | 같은 단서 규칙의 개인 퍼즐, 풀이·힌트 진행 독립 | 개인 도전·대결 |

교사 메뉴에서 개인 도전·개인 대결·팀 대결·공동 목표를 바꿀 수 있게 한다. 각 장르는 모든 방식에 대한 목표·진행·결과 변환 규칙을 갖는다. 협동은 개인 순위를 감추는 것만으로 구현하지 않고 공동 진행량·역할별 기여·공동 끝 조건을 제공한다. 예: 줄다리기 협동은 서로 당기는 두 팀 대신 함께 수학 힘을 모아 물체를 목표선으로 옮긴다. 1인은 개인 목표로 해석하며 선택 변경을 알린다. 학생별 조작은 언제나 독립이며 팀 구성이 순서 대기를 뜻하지 않는다.

공정성 기본값: 비동기 경쟁에서는 같은 문항 순서를 사용하거나 동일한 유형·범위의 동등한 세트를 제공한다. 학생 실력에 따라 문제 난이도를 몰래 바꾸며 같은 순위로 비교하지 않는다. 홀수 인원 팀전은 인원당 기여로 정규화한다. 공통 칸 동시 점령 충돌은 동일 처리 구간의 요청을 추첨하고 미선택자의 점령권을 돌려주는 방식으로 정의한다. 출제 시드 같은 내부 정보는 학생 화면에 표시하지 않는다.

시간은 한 판의 실제 플레이 시간이다. 준비·교사 일시정지는 제외하며, 종료 시 남은 문항은 오답으로 세지 않는다. 동기 진행에서 문항당 시간은 별도 내부 기본값을 두되 남은 전체 시간을 넘기지 않는다. 무제한을 선택하면 장르별 목표·문항 수 또는 교사 종료로 끝난다.

## 7. 프롬프트 생성 구조

생성기는 `선택값 정규화 → 정적 조합 검사 → 장르·운영·테마 계약 결정 → 고정 순서 조립 → 누락·충돌 검사 → 미리보기·복사`로 동작한다. 자료 분석은 ChatGPT의 역할이다. 근거 없는 단원 추정, 출판사별 분기, 자료 적합성 점수를 생성기에 넣지 않는다.

생성기 내부에는 설정 스키마, 20개 장르 데이터, 12개 테마 데이터, 운영 방식 규칙, 공통 프롬프트, 조립기, 화면을 분리한다. 파일은 하나여도 책임은 분리하며 화면 이벤트마다 긴 문자열을 이어 붙이지 않는다. [생성기 설계](generator-architecture.md)에 ID·자료구조·우선순위·조합 검사·출력 검사를 정의한다.

필수 블록:

1. 목표: 첨부 자료를 학습 목표가 유지되는 전자칠판 게임으로 구현.
2. 선택 조건: 장르·디자인·학년·난이도·시간·동시 인원.
3. 자료 계약: 출처 위치, 판독 가능성, 사용·제외 범위, 모호한 부분의 처리.
4. 수학 계약: 생성 가능한 문항 가족, 변수 범위, 불변 조건, 정답·해설·오답 규칙.
5. 게임 계약: 선택 장르의 입력·득점·진행·종료·재시작.
6. 전자칠판 계약: 영역·높이·다중 터치·취소 처리·화면 맞춤.
7. 단일 파일 계약: 인라인 HTML/CSS/JS, 외부 의존 없음 제안.
8. 검증 계약: 수학 검사, 상태 전환, 터치 검사, 수행하지 못한 검증의 표시.
9. 출력 계약: 실행 가능한 완전한 HTML과 짧은 저장 안내. 코드 생략·TODO 금지.

화면은 ‘프롬프트 만들기’라고 부른다. 교사에게 PRD, JSON Schema, 포인터 ID 같은 내부 용어를 이해시키도록 요구하지 않는다.

## 8. 첨부 자료의 문항 변형

문항 가족별 내부 정의는 다음 내용을 포함한다.

`파일/쪽/문항/공통 지문 → 확인 가능한 메타데이터와 문제 내용의 추론을 분리 → 학습 목표 → 원래 풀이 원리 → 변수와 범위 → 기준량·목표량·단위 → 반드시 유지할 조건 → 하/중/상 변형 → 허용된 손동작 → 정답 계산 → 검증 규칙 → 짧은 해설`

학생 응답은 단일 선택, 복수 선택 집합, 관계 연결, 분류, 순서 재배열, 주어진 조각 구성, 구간 선택으로 한정한다. 숫자·분수는 문제와 보기의 값으로 표시할 수 있지만 학생이 키패드로 답을 작성하는 방식은 금지한다. 숫자 카드로 임의 자릿수를 이어 답을 쓰게 하는 우회 구현도 금지한다. 조각 구성은 정해진 수학적 대상의 관계를 조작하며, 유효 상태를 코드로 판정할 수 있어야 한다. 다단계는 허용된 행동 여러 개의 순서다.

‘모두’, ‘아닌 것’, ‘가장 작은’, ‘남은’, ‘그 나머지의’는 판정 조건이다. 복수정답을 단일정답으로 바꾸거나 남은 양을 사용량으로 바꾸지 않는다. 서술형은 근거 카드 선택·풀이 순서 배열 등으로 변환하되 설명 능력 전체를 평가했다고 하지 않는다. 개방형 증명이나 여러 해석을 유한 조작으로 보존할 수 없다면 해당 목표를 제외했다고 숨기지 말고 범위를 질문한다.

분수 판정은 값의 동치성과 표현 형식을 분리한다. 기약분수 목표는 기약분수 보기 선택 또는 주어진 약분 경로 카드 잇기로 변환한다. ‘같은 값 찾기’라면 1/2와 2/4를 하나만 정답인 보기에 함께 넣지 않는다. ‘기약분수 고르기’라면 동치인 약분 전 보기를 값이 다른 오답으로 설명하지 않는다. 수량이 사람·물건의 개수이면 필요한 중간 단계도 정수여야 한다.

예: 같은 분모 진분수의 크기 비교.

- 중 난이도: 분모 d를 정하고, 서로 다른 분자 a·b를 1 이상 d 미만에서 고른다.
- 정답: 같은 분모이므로 분자 비교 결과로 계산한다.
- 하 난이도: 더 작은 분모와 균등 분할 그림을 사용한다.
- 상 난이도: 같은 분모 조건을 유지하며 수직선·빈칸·배열 등으로 판단 형태를 바꿀 수 있다. 서로 다른 분모 비교는 원리·범위가 달라질 수 있어 자동 추가하지 않는다.
- 검증: 분모 0 없음, 진분수 조건, 그림의 동일한 전체 크기와 균등 분할, 답의 유일성.

문제 다양성은 숫자·상황·표현·질문 형태로 나누어 관리한다. 난이도를 올린다는 이유로 미학습 개념을 추가하지 않는다. 원본 문장을 유지할 의무는 없으며 문장제는 적극 압축·재구성한다. 다만 원래 목표가 상황 해석·연산 선택·비교 기준 이해라면 짧은 상황과 식 선택 등으로 그 판단을 남긴다.

변형 예: ‘24개의 구슬을 한 봉지에 6개씩 담는다’라는 긴 상황은 목표가 나눗셈 연습이면 `24 ÷ 6`으로 바꿀 수 있다. 목표가 포함제 상황에서 나눗셈식을 세우기이면 `구슬 24개 · 봉지당 6개 → 봉지 수를 구하는 식 고르기`로 바꾼다. 등장인물·장식 문장은 지워도 무엇을 구하는지는 유지한다. 핵심 제약의 삭제와 표현의 단순화를 구분한다.

화면당 짧은 지시문과 한 과제를 기본으로 삼는다. 같은 학습 목표의 대표 문항 가족 1~3개와 변형 함수를 기본 제작 단위로 삼되 숫자를 맞추기 위해 중요한 목표를 누락하지 않는다. 여러 목표가 한 게임에서 명확히 함께 다뤄지면 혼합하되 유형별 출제 비중을 둔다. 묶을 수 없는 서로 다른 목표가 경쟁하면 초점만 한 번 질문한다.

파일명·출판사·기본/심화 표시는 학습 범위의 근거로 충분하지 않다. 단원·차시·학년 표기가 없으면 수의 종류, 연산, 관계, 도형, 단위, 질문과 풀이 단계에서 목표를 추론한다. 예: 제목 없는 2/3×3/5는 ‘진분수의 곱’으로 다루며 정확한 학년·차시를 꾸며 쓰지 않는다. 학년 미상 자체는 질문 사유가 아니다. 교사가 학년을 지정했으면 이를 대상 수준으로 쓰되 자료와 개념 범위가 충돌하면 묻는다.

자료 2개는 첫 자료=주자료로 가정하지 않는다. 같은 개념이면 통합, 문제지+해설이면 교차 확인, 다른 표현의 같은 목표면 연결, 상이한 목표이고 범위 미지정이면 초점 질문이다. 같은 단원 안의 표현 차이만으로 질문하지 않는다. 교사 검토 화면에는 확인된 내용·추론한 목표·사용/변환/제외 범위를 구분한다. 중요한 목표 누락이나 흐린 핵심 문항을 임의 제외해 자료 전체 반영이라고 표시하지 않는다.

문서 판독에서 분수선·수직선 경계점·표·카드·공통 지문을 확인한다. 추출 문자열에 그림 정보가 없으면 없는 문제라고 판단하지 않는다. 원문이 확인 가능한 경우 시각 구조로 보완하고, 결정적인 조건을 확인할 수 없을 때만 해당 쪽·문항을 질문한다.

HTML 실행 중에는 작성된 JavaScript가 문항을 만든다. 문제 목록을 섞는 것과 변수에서 새 문제를 생성하는 것을 구분한다. 문제·정답·오답·해설·도형을 하나의 수학 데이터에서 만들고, 오답은 흔한 개념 혼동에서 구성하되 중복·동치·복수 정답을 검사한다. 학생 손동작은 이 데이터에 대한 선택이나 상태 변경이며 실행 중 LLM이 새 문제를 해석하지 않는다.

중복 정책 제안: 최근 문항의 표준화 키를 기억해 반복을 줄인다. 가능한 조합이 소진되면 기록 일부를 비우고 재사용한다. 생성 시도에는 상한을 두며, 실패 시 현재 학습 조건에 맞는 검증된 예비 문항을 사용한다. 엉뚱한 ‘1+1’ 문제로 대체하지 않는다.

## 9. 전자칠판 필수 계약 제안

- 1~6명 선택과 동시 입력을 지원한다. 기기 문제를 이유로 임의로 순차 플레이로 바꾸지 않는다.
- 학생별 입력·답안·잠금·피드백·진행 상태를 분리한다. 한 학생의 오답이 다른 학생을 멈추지 않는다.
- 화면을 상단 관람 영역과 하단 조작 영역으로 분리한다. 학생이 누르거나 끌어야 하는 모든 시작점·도착점·확정·취소·힌트는 하단 조작 영역 안에 둔다. 상단의 보스·레이스·지도·큰 도형은 보기 전용이며 대응하는 조작을 하단에 제공한다.
- 학생 조작 영역의 위쪽 경계는 기본 화면 높이의 65%, 교사 조절 범위는 60~80%로 제안한다. 60%보다 위로 올리는 옵션은 두지 않는다. 이는 물리적 도달 높이를 보장하는 값이 아니며 교사가 설치 높이에서 확인한다. 공간이 부족하면 선택 단계·카드 수를 줄이고 보드 폭을 안내하며 위쪽으로 조작을 밀어 올리지 않는다.
- 6인은 하단의 가로 6개 개인 구역을 기본으로 한다. 위·아래 학생 줄을 만드는 2×3 배치 금지. 각 구역 안 보기 카드는 2열 등으로 배치할 수 있다. 긴 보기 대신 짧은 값·식·그림을 쓰되 핵심 조건을 삭제하지 않는다. 연결의 양 끝과 조립판도 해당 개인 구역에 둔다.
- 주요 터치 대상은 최소 64 CSS px, 대상 간격 8 CSS px를 설계 기준으로 제안한다. 숫자가 아니라 실제 버튼 경계로 검사한다. 큰 분수·그림이 필요한 경우 더 넓게 배치한다. 글자를 무작정 축소하거나 학생 조작에 스크롤을 요구하지 않는다. 지원 화면 안에서 성립하지 않으면 기능 완성으로 판정하지 않는다.
- 숫자·분수 키패드, 텍스트 답안, 손글씨·카메라 인식, 임의 숫자 조합 답안은 제공하지 않는다. 드래그 정밀도가 수학 점수를 좌우하지 않으며 넓은 스냅 영역과 선택→대상 탭 대안을 제공한다.
- 드래그는 손가락별로 추적하고 취소·영역 이탈·포인터 캡처 해제를 처리한다. 가능하면 두 번 탭 대안도 제공한다.
- 포인터를 누른 개인 구역에 소유권을 고정하고 다른 학생 구역으로 넘어가도 이관하지 않는다. `pointerId`별 상태와 `pointercancel`·`lostpointercapture` 처리를 제공한다. `touch-action: none`은 학생 조작 영역에 적용하고 교사 메뉴의 필요한 스크롤은 유지한다.
- 하나의 행동으로 한 번만 채점한다. 중복 이벤트·연타·여러 손가락의 같은 답 제출을 처리한다.
- 탭 전환·교사 일시정지 시 시간과 게임 움직임이 함께 멈추며 복귀 후 임의 진행하지 않는다.
- 시작 카운트다운 이전·일시정지 중·종료 후에는 득점 입력을 무시한다.
- 재시작 시 타이머·이전 애니메이션·지연 콜백을 정리한다.
- 전체화면 요청이 거절되어도 일반 창에서 사용할 수 있어야 한다.
- 교사 메뉴에 일시정지·이어하기·처음부터·소리·조작대 높이·문제 검토를 둔다.
- 초기 화면에 실제 입력이 몇 개 전달되는지 확인하는 짧은 터치 확인 기능을 제안한다. 지원 여부를 추측해 ‘6인 검증 완료’로 표시하지 않는다.
- 조작대 높이 변경은 진행을 일시정지하고 진행 중 드래그를 취소한 뒤 배치한다. 학생이 터치하는 도중 목표가 이동하지 않게 한다. 브라우저 크기·배율 변화도 같은 원칙으로 처리한다.

### 화면 복제·확장 지원

- 게임 한 창에서 모든 기능이 동작한다. 복제 모드는 같은 화면을 함께 보는 방식이며, 교사만의 별도 비밀 화면을 전제로 하지 않는다.
- 확장 모드에서는 교사가 게임 창을 전자칠판 화면으로 옮겨 연다. 안내는 ‘게임 창을 칠판 쪽으로 옮긴 뒤 전체화면’을 기본으로 하고 모니터 설정을 자동 변경하지 않는다.
- 포인터 좌표는 현재 요소의 표시 영역을 기준으로 계산한다. 모니터의 전역 위치를 게임 좌표로 사용하지 않는다.
- canvas는 CSS 표시 크기와 그리기 해상도를 분리하고 현재 요소의 경계·배율로 입력 위치를 변환한다.
- 창 이동·크기 변경·전체화면·Windows 배율 차이 이후 레이아웃과 좌표 매핑을 갱신한다. 터치 표시점과 게임 판정 위치가 일치해야 한다.
- 실제 보드가 잘못된 모니터에 터치를 보내는 Windows 장치 설정 문제는 HTML이 수정할 수 있다고 안내하지 않는다. 터치 확인 화면에서 증상을 구별하고 일반 마우스 입력도 비교할 수 있게 한다.

## 10. 단일 HTML과 오프라인 제안

생성기와 게임은 각각 하나의 HTML 파일로 제공한다. 두 파일은 역할이 다르다. 게임 제작 과정의 ChatGPT 이용에는 인터넷이 필요하다.

생성기·완성 게임의 실행은 CDN, 외부 폰트, 외부 그림, 네트워크 요청, 서버, API 키 없이 가능하도록 하는 방안을 권장한다. 시각 자료는 인라인 SVG·CSS·canvas로 구성한다. 인터넷 차단 상태에서 file://로 여는 검증을 별도로 수행한다.

설정 저장은 실패해도 게임 실행을 막지 않으며, 생성기는 복사 실패 시 전체 선택과 TXT 저장을 제공한다. 브라우저 저장 기능만 믿지 않고 설정 내보내기·가져오기를 추가 기능으로 고려한다.

## 11. 초보·시니어 교사를 위한 편의 기능

- 번호가 보이는 짧은 사용 흐름과 클릭 가능한 큰 카드.
- 현재 선택을 한 문장으로 보여주는 요약.
- 장르마다 ‘학생이 하는 행동’ 설명과 정적 미리보기. 생성할 실제 게임 화면이라고 오인시키지 않음.
- 모든 항목에 추천값이 있어 상세 설정을 열지 않아도 사용 가능.
- ‘ChatGPT에 활동지와 함께 붙여넣으세요’ 안내와 자료에서 학생 이름을 가리라는 짧은 준비 안내.
- 프롬프트 복사, 복사 실패 시 대안, TXT 다운로드, 설정 초기화.
- ‘HTML 저장 방법’에서 코드 전체 선택, `.html` 확장자, UTF-8, 브라우저 실행을 설명.
- 생성 모델이 실제 파일을 첨부할 수 없을 때 코드 전체를 저장하는 대안. 존재하지 않는 다운로드 링크를 만들도록 요구하지 않음.
- 수정 요청 템플릿: ‘문제가 잘못됐어요’, ‘버튼이 잘려요’, ‘동시 터치가 안 돼요’, ‘더 쉽게/어렵게’, ‘다른 디자인’.
- 완성 게임의 교사 설정에서 인원·시간·난이도·운영 방식·팀 구성·소리·조작 높이를 변경한다. 인원·시간·난이도·운영 방식·팀 구성은 다음 판, 소리는 즉시, 높이는 일시정지 후 즉시 적용한다. 현재 판을 바꾸려면 ‘설정으로 새 판 시작’을 명시적으로 누른다.
- 사진·PDF를 모두 안내하고 ‘PDF 파일 쪽’과 ‘인쇄된 교과서 쪽’이 다를 수 있어 범위를 구별해 적을 수 있게 한다. 여러 파일은 파일명과 쪽을 함께 지정하도록 돕는다.

## 12. 수용 기준과 시험 계획

아래는 제품 전체의 수용 기준이다. 실제로 수행한 조립기·공통 입력·디자인 시제품 시험과 아직 남은 게임 생성·물리 시험은 [자체 검증 보고서](self-verification-2026-09-10.md)에서 구분한다.

| 층위 | 수용 기준 |
|---|---|
| 생성기 | 선택값이 모두 반영되고 선택하지 않은 장르 규칙이 섞이지 않음 |
| 생성기 | 같은 선택은 같은 프롬프트를 생성, 누락된 치환 변수 없음 |
| 생성기 | 복사·TXT 저장·초기화·키보드 조작·큰 글자 환경 동작 |
| 자료 해석 | 출처 범위와 학습 목표가 맞고 판독 불가 내용을 꾸미지 않음 |
| 수학 | 유형별 대표·경계값, 정답·해설·그림 일치, 중복 보기·0 분모·불가능 조건 없음 |
| 무작위 생성 | 지원 문항 가족·난이도마다 여러 고정 시드 및 충분한 표본을 독립 검증, 생성 실패 시 무한 루프 없음 |
| 게임 | 시작·정답·오답·일시정지·종료·동점·재시작이 일관됨 |
| 다중 입력 | 실제 보드에서 1~6명 입력과 드래그 취소, 같은 영역 연타, 서로 다른 영역 동시 답 제출 검증 |
| 화면 | 1280×720, 1366×768, 1920×1080 및 실제 보드에서 주요 조작 잘림 없음 |
| 모니터 | Windows 화면 복제·확장, 게임 창 이동, 전체화면 전환, 다른 배율에서도 터치 좌표와 버튼 일치 |
| 접근성 | 글자 크기·고대비·소리 끄기·움직임 줄이기·탭 대안 적용 |
| 오프라인 | 네트워크 차단 후 로컬 HTML 실행 및 재시작 가능 |
| 무료 ChatGPT | 무료 계정에서 대표 자료·프롬프트 생성 실험. 최초 완성률과 수정 1회 후 완성률, 정답 오류, 코드 잘림을 별도 기록 |

대표 자료 제안: 받아올림 있는 자연수 연산, 몫·나머지, 같은 분모/다른 분모 분수, 소수, 규칙, 비례, 시계·단위, 평면도형, 표·그래프, 문장제, 흐린 이미지와 혼합 유형 자료. 실제 학년·단원 적합성은 사용 자료로 확인한다.

첫 품질 관문은 쉬운 장르·어려운 장르·6인·짧은 화면·분수·그래프·모호한 자료를 포함한다. 임의로 전체 조합 성공을 주장하지 않는다. 검증용 정답은 생성 함수와 같은 오류를 공유하지 않도록 독립 계산과 교사 검토를 병행한다.

무료 환경의 품질 비교: A안은 정제한 제작 계약, B안은 동일 조건에 시험한 공통 입력 상태 코드를 추가한다. [A안 예시](example-prompt-coop-match.txt)와 [B안 예시](example-prompt-coop-match-reference.txt)를 만들었다. B의 입력 코드는 자체 시험했지만 완전한 게임 골격은 아니며 모델의 통합 정확성·출력 길이는 별도로 검증해야 한다. 현재 시제품 기본값은 A다. 실제 무료 계정에서 같은 자료·조건으로 첫 출력 완결성과 수정량을 비교하기 전에는 B가 더 우수하다고 단정하거나 기본으로 강제하지 않는다.

최소 출시 기준 제안: 대표 자료로 정답 오류 없이 실행되는 결과를 확보하고, 20개 유형 각각 최소 한 번의 제작·플레이 사례를 확인한다. 대표 6개는 새 대화에서 3회씩 반복해 우연한 성공을 구별한다. 동시 조작은 물리 보드에서 6인 검증을 별도로 통과해야 한다. ‘LLM이 자체 점검했다고 답함’을 수용 시험 통과로 계산하지 않는다. [상세 설계의 시험 계획](generator-architecture.md)에 자료 일반화·하단 경계·전체 모드·조립기 조합 검사를 정의한다.

필수 추가 사례: 학년·제목 없는 문제, 다른 학년/단원 자료 2개, 문제지+해설, 사진만 있는 자료, 일부 쪽 지정, 근거 서술형 변환, 핵심 조건 판독 불가. 주관식 0·필수 상단 터치 0·동시 참여를 순차로 바꾸는 처리 0을 실패 판정 기준으로 둔다. 현재 샘플 6개는 전 학년 일반화의 증거가 아니다.

재미는 장르 고유 행동이 실제 진행을 바꾸는지, 수학 선택이 다음 상태에 영향을 주는지, 오답 뒤 다시 참여할 수 있는지, 협동의 공동 변화가 보이는지로 시험한다. 빠른 조작과 장식량으로 이를 대체하지 않는다. 프롬프트가 상세하다는 이유로 최초 완성률 100%를 주장하지 않는다.

## 14. 실제 활동지로 확인한 첫 검증 대상

[활동지 분석 보고서](worksheet-analysis-2026-09-10.md)에 6개 파일의 문항 구조, 게임화 예시, 생성 제약을 정리했다. 두 단원(수의 범위와 어림하기 / 분수의 곱셈)을 분리한다.

첫 게임 시험 후보는 이상·이하 분류 게임, 진분수 곱셈의 기약분수 보기 선택 레이싱, 남은 양을 새 기준으로 삼는 보스전이다. 각각 경계·집합, 유리수·동치 보기, 중첩 기준량이라는 서로 다른 실패 요인을 검증한다.

대표 원문 문항 17개 재계산과 수학 규칙 조합 7943개를 확인했다. 이것은 정확한 유리수 기반 연구용 계산 검토이며 LLM 생성 결과나 완성 게임의 시험 통과를 뜻하지 않는다. 기록은 [수학 검토 결과](worksheet-math-checks.json)에 있다.

## 15. 생성기 디자인과 교사 사용성

[디자인 명세](generator-design-spec.md)를 제품 요구사항으로 채택한다. 제품명은 ‘수학 공작소’이며, 성인 교사용 설계 도구로서 쉬운 단어·구체적인 설명을 사용하고 어린이에게 말하는 문체를 사용하지 않는다. 생성기 화면은 정돈된 작업 도구로 유지하고, 선택 가능한 12개 결과 테마는 진행 HUD·임무·보상·세계관이 명확한 게임 화면으로 구성한다.

게임 이름은 레이싱·슈팅·디펜스·미로·조립 퍼즐처럼 익숙한 장르를 앞세운다. 선택한 게임의 ‘학생 조작’과 ‘게임 진행’을 각각 설명해 실제 수업을 예상할 수 있게 한다. 20개 목록과 검색을 제공하며 배경만 다른 같은 게임을 별도 장르로 세지 않는다.

12개 테마는 색상 점 대신 실제 SVG 장면으로 비교한다. 같은 문제 카드·하단 조작 영역을 서로 다른 배경·패널·모서리·장식으로 보여주고 확대 미리보기를 제공한다. 선택 테마의 팔레트를 프롬프트에 전달하며 실제 생성 결과를 미리 보여준다고 주장하지 않는다.

넓은 화면은 왼쪽 설정·오른쪽 요약과 미리보기, 좁은 화면은 한 열이다. 복사 버튼이 그림 때문에 밀려나지 않게 한다. 본문 18px·설명 16px·일반 조작 높이 48px 이상을 기준으로 하며 대비·키보드 초점·복사 실패 대안을 검사한다.

[단일 HTML 시제품](../prototypes/generator-design.html)에서 선택·이미지 미리보기·프롬프트 조립·복사·TXT 저장을 확인할 수 있다. 생성기의 업무 화면과 생성할 학생 게임의 12개 테마는 구별한다.

## 16. 6인 입력에서 추가한 필수 불변 조건

- `isPrimary`만 받는 필터는 금지한다. 첫 번째 손가락 이외의 정상 입력도 처리한다.
- 포인터 소유권은 개인 구역뿐 아니라 시작한 판 ID·문항 revision과 연결한다. 새 문항/새 판에 이전 손 떼기가 적용되지 않는다.
- 포인터 캡처 중 `event.target`은 출발 요소일 수 있다. 손 뗀 좌표의 실제 도착 대상을 검사한다.
- 한 학생의 처리에 전체 학생 DOM을 다시 생성하지 않는다. 다른 학생의 포인터·답안·피드백은 유지한다.
- 판정·보상 잠금은 동기적으로 확정하고 연출을 나중에 수행한다. `pointer`와 호환 `click` 이벤트를 이중 처리하지 않는다.
- 지연 콜백도 예약한 판·문항과 현재 상태가 맞아야 적용한다. 일시정지·탭 숨김·포커스 상실·배치 변경은 진행 포인터와 선택 상태를 정리한다.
- 조립·퍼즐은 수학적으로 유효한 최종 상태에서만 완료를 판정한다. 단순 입력 참조 코드가 수학 검증을 대신하지 않는다.

구현 참조는 [입력 상태 코드](../prototypes/input-kernel.js), 실행 시험은 [하단 입력 검증실](../prototypes/input-lab.html)이다. 이 시제품에서 6개 접점은 브라우저로 모사했고 실제 학생·전자칠판 드라이버의 시험은 남아 있다.

## 17. 프롬프트 품질과 출시 판단

현재 조립기의 전체 기본 조합 113,400개를 검사했다. 이는 문항 해석·HTML 생성·장르별 게임 품질을 증명하지 않는다. 실제 무료 생성 시험은 자료 판독→목표 보존→새 문항/보기 정확성→실행 완결→동시 조작→장르 고유 행동을 각각 기록한다. 중요한 항목 하나라도 실패하면 종합 점수로 상쇄하지 않는다.

정상 자료는 질문 없이 제작하는지, 모호한 핵심 자료는 특정 부분만 질문하는지 모두 시험한다. 교사 검토의 예시는 실제 출제 함수에서 만들어야 하며 별도의 정상 예시로 잘못된 엔진을 가리지 않는다. 문항뿐 아니라 오답 보기 생성에도 재시도 상한을 둔다. 안전 정수 범위를 벗어나는 분수 교차곱·소수 배율·조합 계산을 만들지 않는다.

최초 출력과 수정 후 결과를 분리한다. 같은 사례의 A/B 비교는 화면에 표시된 무료 모드와 자료 접근 가능 여부를 기록하고 새 대화에서 수행한다. 모드·계정 조건이 달라지면 합산하지 않는다. 현재 자체 시험은 알려진 구현 실패를 줄이는 근거이며, 무료 생성 성공률 향상을 실측한 결과는 아니다.

### 프롬프트 명료화 및 저작권 보완

기본 프롬프트는 구현 순서 5단계, 용어 풀이, 학생별 입력 처리 절차, 관찰 가능한 완료 조건을 포함한다. 선택/이동 중 임시 답안과 최종 채점을 구별하고, 학습·조작 제약을 장식보다 우선한다. 상세 원문은 프롬프트 계약 1.2를 따른다. 생성기 하단에는 `© 2026 찰떡쌤. All rights reserved.`를 한 번 표시한다. 자체 검증은 조립기·참조 입력 구현에 대한 결과로 기록하며 미래 생성물이나 실제 칠판의 성능을 보장하는 문구로 전환하지 않는다.


### 디자인 3.0 및 선택 흐름 개정

화면 배치는 generator-design-spec.md의 3.0을 최신 사양으로 적용한다. 대표 게임 8개에서 전체 20개를 펼칠 수 있고, 선택한 게임은 접은 상태에서도 유지·표시한다. 디자인 12개는 색상 견본으로 제공하며 실제 장면 미리보기는 선택한 1개만 표시한다. 작업 패널의 정렬과 간격을 통일하고 별도 요약 영역은 복사·다음 사용 순서에 집중한다. 프롬프트 생성 계약과 단일 파일·오프라인 조건은 유지한다.
