# 수학 공작소 디자인 5.0 · 패널 위계와 컬러 시스템

2026-09-10. 아래 5.0 사양이 생성기 패널·간격·색상 위계에 관한 기존 사양을 대체한다.

- 도입부를 하나의 옅은 민트 패널로 묶고 핵심 수치 3개를 짧은 칩으로 제공한다.
- 게임 유형, 수업 조건, 게임 분위기를 각각 하나의 독립 패널로 사용한다. 내부 선택마다 추가 패널을 남용하지 않는다.
- 패널 헤딩은 같은 구조를 유지하되 게임 유형은 초록, 수업 조건은 파랑, 게임 분위기는 주황으로 구분한다. 숫자 배지·옅은 헤딩 배경·선택 상태에 같은 계열 색을 반복하여 위치를 쉽게 파악하게 한다.

- 선택한 게임 설명과 디자인 미리보기만 보조 패널을 사용한다. 전자는 초록 왼쪽 선, 후자는 주황 계열 배경으로 상위 섹션과 연결한다.
- 프롬프트 복사 패널은 상단 진행색 띠와 초록 버튼으로 주요 행동을 강조한다. 보조 행동은 하단 텍스트 버튼으로 낮춘다.
- 그림자, 테두리, 둥근 모서리의 강도를 통일하고 `prefers-reduced-motion`에서 모든 전환 효과를 제거한다.

# 수학 공작소 디자인 4.0 · 교사는 편하게, 결과는 게임답게

2026-09-10. 아래 4.0 사양이 테마 명칭과 디자인 선택 경험에 관한 기존 사양을 대체한다.

- 생성기 자체는 교사가 오래 보아도 피로하지 않은 정돈된 작업 화면을 유지한다. 생성될 학생용 게임 테마는 HUD, 미션, 진행 게이지, 단계, 수집·보상 요소가 보이는 게임 화면으로 구분한다.
- 제품명은 `수학 공작소`, 큰 제목은 `수학 게임 공작소`다. 지정된 도입 문구 3줄을 그대로 사용한다.
- 12개 테마 이름은 게임 세계와 목표가 바로 떠오르는 이름을 사용한다. 조용한 문서·메모장·추상 색상 스타일은 테마 후보로 사용하지 않는다.
- 선택 버튼은 테마 아이콘, 이름, 한 줄 게임 경험을 제공한다. 선택한 한 개의 큰 장면만 표시하여 미리보기 과밀을 막는다.
- 큰 장면은 동일 수학 문제를 사용하되 상단 HUD, 미션 번호, 진행 게이지, 시간·별 보상, 하단 개인 조작 구역을 보여 준다. 장식이 수학 정보와 조작 영역을 가리지 않는다.
- 프롬프트에는 색상값뿐 아니라 테마 모티프와 게임 반응을 포함한다. 정답이 게이지·경로·수집물·대상을 바꾸며, 짧은 반응과 단계 전환으로 흥미를 만든다.

# 생성기 디자인 3.0 · 간결한 작업 화면

2026-09-10. 아래 3.0 사양이 기존 2.0의 배치·색상·미리보기 수량 사양을 대체한다. 기존 내용은 변경 전 기록이다.

- 중성 배경 #f5f6f5, 짙은 본문 #202b2b, 절제된 녹색 강조 #236555. 장식보다 정렬·여백·명확한 선택 상태로 위계를 만든다.
- 왼쪽의 한 작업 패널을 게임 / 수업 조건 / 디자인으로 구분한다. 여러 카드의 중첩 대신 구분선을 사용한다.
- 첫 화면은 대표 게임 8개. 전체 20개 펼치기/접기와 설명 검색을 제공한다. 접어도 현재 선택은 표시하며 설정을 잃지 않는다.
- 디자인은 12개 색상 견본으로 선택한다. 게임 화면 미리보기는 선택한 디자인 1개만 표시하며 별도 확대가 가능하다.
- 오른쪽은 선택한 수업·복사·사용 순서에 집중한다. 충분한 화면 높이에서만 스크롤에 따라 유지하고 좁은 화면에서는 본문 뒤에 놓는다.
- 상세 자료 범위와 추가 조건은 접힌 영역에 유지한다. 주요 입력의 폭·간격·라벨 정렬을 일관되게 한다.
- 브랜드와 제품명은 수학 공작소. 안내는 성인 교사를 대상으로 간결하게 쓴다. 선택 상태는 배경·윤곽·굵기로 표시하고 키보드 초점을 제공한다.
- 저작권은 기존 문구를 본문 다음 일반 흐름으로 유지한다.

검증: 320~1440px 6개 화면 폭, 200% 상당 CSS 화면 폭, 선택/확대/복사/다운로드/오프라인을 포함한 브라우저 15항목, 색상 대비 42쌍. 실제 시니어 교사 사용자 시험을 수행한 결과는 아니다.

# 프롬프트 생성기 디자인 명세

버전 2.0 / PRD 2.2 부속 / 2026-09-10. [작동하는 디자인 시제품](../prototypes/generator-design.html)을 함께 제공한다. 이 문서는 현재 디자인 기준이며 이전의 교실·노트 장식 방향을 대체한다.

## 1. 사용자는 성인 교사다

설명은 쉬운 단어와 구체적인 행동으로 쓰되 교사를 어린이처럼 대하지 않는다. 제품명은 ‘수학 공작소’다. 헤더는 ‘활동지 1개로, 선생님이 원하는 게임을 디자인하세요. / 수학 게임 공작소 / 선생님의 취향에 맞게 프롬프트를 만들어줄거에요.’ 순서로 표시한다.

‘쉽다’는 것은 짧기만 하다는 뜻이 아니다. 교사가 장르를 선택한 뒤 학생이 무엇을 누르는지, 수학 판단이 어떻게 진행을 바꾸는지 예상할 수 있어야 한다. 화면의 설명은 학생에게 보내는 안내가 아니라 수업을 설계하는 교사에게 제공하는 정보다.

| 피할 표현 | 사용할 표현 |
|---|---|
| 어떻게 풀어 볼까요? | 게임 유형 |
| 우리 수업에 맞춰요 | 수업 조건 |
| 복사했어요 | 프롬프트를 복사했습니다 |
| 친구들과 힘을 모아요 | 학생들의 기여로 공동 목표를 완성합니다 |
| 제목·설명 없이 ‘수학 레이싱’만 표시 | 레이싱 + 학생의 경로 선택과 차량 이동 설명 |

생성기 내부 문구는 ‘합니다/하세요’를 기본으로 한다. 학생 게임 안의 문구는 연령에 맞게 별도로 설계한다. ‘학년을 몰라도 괜찮아요’ 같은 위로보다 ‘학년·차시가 없어도 문제 내용에서 학습 목표를 파악합니다’처럼 기능을 설명한다.

## 2. 시각 방향

교사용 설계 도구답게 중립적인 회색 바탕과 흰색 작업 영역, 선명한 짙은 글자, 한 가지 파란 강조색을 사용한다. 분필·나무 칠판 테두리·노트 번호 장식·동물 캐릭터는 생성기 화면의 정체성으로 사용하지 않는다.

개성은 다음 세 부분에서 만든다.

- 장르명은 익숙하게, 선택한 게임의 작동 방식은 구체적으로 설명한다.
- 같은 수학 장면을 12개의 실제 시각 구성으로 보여주어 디자인을 비교한다.
- 선택값과 완성될 프롬프트의 관계를 수업 요약에서 즉시 확인한다.

모든 내용을 똑같은 홍보 카드로 늘어놓지 않는다. 장르는 간결한 선택 목록, 설명은 별도 정보 영역, 테마는 이미지 갤러리, 최종 행동은 설정 요약으로 구별한다. 과장된 그라데이션·반짝임·AI 배지·장식적인 영어 제목을 추가하지 않는다.

## 3. 게임 이름과 설명

20개 표시 이름: 퀴즈, 레이싱, 줄다리기, 보스전, 디펜스, 슈팅, 빙고, 선 잇기, 카드 뒤집기, 분류 게임, 미로, 순서 퍼즐, 조립 퍼즐, 블록 합치기, 영역 점령, 저울 퍼즐, 어림 과녁, 패턴 퍼즐, 상점 경영, 추리 퍼즐.

카탈로그 ID와 수학·입력 계약은 유지한다. 장르 이름만 바꿔 같은 게임을 여러 개로 세지 않는다. 퍼즐의 하위 유형은 조립·순서·패턴처럼 행동 차이를 이름에서 보여준다.

선택한 장르에는 다음 두 설명이 필수다.

| 정보 | 작성 기준 | 레이싱 예시 |
|---|---|---|
| 학생 조작 | 무엇을 보고 무엇을 선택/이동하는지 | 문제의 답이나 조건에 맞는 이동 경로를 선택합니다. |
| 게임 진행 | 선택이 게임 상태와 목표를 어떻게 바꾸는지 | 해결 결과에 따라 차량이 전진합니다. 갈림길 선택이 이동 거리와 다음 과제에 영향을 줍니다. |

디펜스는 ‘문제를 해결해 방어 자원을 얻고 배치 위치를 선택 / 적 이동과 전투는 자동’, 슈팅은 ‘표적 카드 선택 / 자동 발사’처럼 컨트롤과 수학의 역할을 구분한다. 선 잇기와 카드 뒤집기는 공개된 관계 연결과 숨긴 카드 위치 기억의 차이를 설명한다.

전체 20개를 간결한 목록에서 볼 수 있고, ‘게임 설명·검색’ 대화상자에서는 설명을 함께 비교한다. 검색이 없더라도 이름만 보고 탐색할 수 있어야 한다. ‘새 게임 구상’과 교사 아이디어 입력은 별도 경로로 유지한다.

## 4. 디자인은 이미지로 비교한다

색상 점만으로 선택시키지 않는다. 12개 테마마다 실제 SVG 장면을 제공하며, 선택하면 큰 미리보기와 톤 설명이 바뀐다. ‘미리보기 확대’로 더 큰 이미지를 볼 수 있어야 한다. 이미지·스타일·스크립트는 단일 HTML에 포함하고 외부 파일이나 네트워크를 요구하지 않는다.

비교 장면은 동일한 문제 카드와 하단 학생 조작 영역을 사용한다. 배경·패널 색·모서리·장식·선의 차이가 보여야 한다. 내용이 다른 그림끼리 비교해 테마 차이를 파악하기 어렵게 하지 않는다. 축소 그림의 작은 글씨는 실제 학생 화면 글자 크기의 기준이 아니다.

| ID | 표시 이름 | 미리보기에서 확인할 시각 차이 |
|---|---|---|
| classroom | 챌린지 스타디움 | 에너지 게이지·미션 배지·별 보상이 있는 밝은 경기 화면 |
| space | 갤럭시 미션 | 행성 궤도·연료 게이지·탐사 단계가 있는 우주 임무 |
| forest | 정글 어드벤처 | 정글 경로·탐험 배지·보물 조각을 모으는 모험 |
| ocean | 딥씨 트레저 | 잠수정·산소 게이지·보물 상자가 있는 해저 원정 |
| pixel | 픽셀 퀘스트 | 픽셀 하트·스테이지·코인이 있는 레트로 게임 |
| sports | 챔피언 아레나 | 경기장·팀 게이지·챔피언 배지가 있는 스포츠 대결 |
| paper | 보물섬 탐험 | 나침반·점선 경로·보물 상자가 있는 지도 모험 |
| block | 블록 팩토리 | 조립 블록·생산 게이지·완성 기계가 있는 공장 퍼즐 |
| dessert | 캔디 팝 | 캔디 조각·콤보 숫자·별 폭발이 있는 캐주얼 게임 |
| dinosaur | 다이노 원정대 | 발자국 경로·화석 조각·탐사 단계가 있는 공룡 탐험 |
| robot | 로봇 커맨드 | 회로·전력 게이지·시스템 배지가 있는 미래 임무 |
| fantasy | 매직 킹덤 | 마법 수정·퀘스트 단계·빛나는 별이 있는 판타지 모험 |

내부 ID는 호환성을 위해 유지한다. 테마마다 배경·본문·카드·강조·보조 글자 색을 데이터로 관리하고 프롬프트에도 해당 값을 반영한다. 미리보기는 디자인의 근사 예시이며 실제 자료를 분석한 게임 결과로 표시하지 않는다. 장르·자료가 달라져도 색상과 톤의 기준은 전달된다.

## 5. 화면 구조

1. 머리말: 제품의 기능 이름과 사용 방법.
2. 도입: 생성기의 역할을 한 문장으로 설명.
3. 게임 유형: 20개 선택, 선택한 게임의 학생 조작·진행 설명, 검색, 새 구상.
4. 수업 조건: 인원·운영·시간·난이도. 범위·학년·목표·아이디어는 상세 설정.
5. 디자인: 12개 이미지 갤러리, 선택 상태, 확대 미리보기.
6. 설정 요약: 선택한 장르·인원·방식·시간·난이도, 복사, TXT 저장.
7. 큰 미리보기: 선택 디자인의 예시 장면과 톤 설명.

넓은 화면은 왼쪽 설정과 오른쪽 요약/미리보기다. 요약의 복사 버튼을 큰 이미지보다 먼저 보여준다. 높이가 부족하면 오른쪽 전체 고정을 해제하고 버튼이 화면 밖에 고정되지 않게 한다. 800px 이하에서는 설정→요약→미리보기 한 열로 전환한다.

장르는 넓은 화면에서 4열, 좁은 화면에서 3열까지 사용한다. 테마는 3열, 좁은 화면에서는 2열로 배치한다. 긴 이름은 줄바꿈하며 생략하지 않는다. 교사용 생성기의 모바일 배치와 학생 게임의 6인 하단 배치는 서로 다른 계약이다.

| 선택 표면 / 글자 | #EEF2FF / #2648B2 |
| 입력 경계 / 포커스 | #8290A4 / #8B461F |
| 일반 구분선 | #D9DFE8. 조작 경계와 구별 |
| 기본 글꼴 | Malgun Gothic, Apple SD Gothic Neo, sans-serif |
| 본문 / 설명 | 18px / 16px |
| 섹션 / 큰 제목 | 23px / 27~32px |
| 일반 조작 | 높이 48px 이상, 짧은 인원 선택 폭 44px 이상 |

선택한 장르는 색·테두리·굵기·체크로 구분한다. hover는 선택처럼 보이지 않게 한다. 테마 이름과 선택 표식은 이미지 밖의 읽을 수 있는 텍스트로 제공한다. 배경 장식과 축소 예시의 작은 글자는 교사 설명이나 실제 학생 버튼 크기를 대신하지 않는다.

본문 대비 4.5:1, 주요 조작 경계·포커스 3:1을 기준으로 한다. 테마의 본문·문제 카드·설명 대비도 별도로 계산한다. 외부 폰트가 없어도 한글이 명확하게 보여야 한다. 가로 320 CSS px, 200% 확대에 해당하는 좁은 화면에서도 가로 넘침 없이 기능에 도달해야 한다.

## 7. 상호작용과 설명의 완결성

- 입력 레이블은 항상 표시하고 placeholder만으로 의미를 전달하지 않는다.
- 자료 범위는 ‘첫 번째/두 번째 자료’ 표지를 유지한다. 첨부는 ChatGPT에서 하며 가짜 업로드 화면을 만들지 않는다.
- 학년은 지정하지 않아도 된다. 생성기에서 자료를 분석한 것처럼 표시하지 않는다.
- 모든 선택은 요약·미리보기·프롬프트에 함께 반영한다. 키보드 초점을 잃는 전체 DOM 교체를 하지 않는다.
- 복사는 실제 성공 후만 완료 표시. 거부되면 전체 본문·전체 선택·수동 복사·TXT를 제공한다.
- 대화상자에는 읽을 수 있는 제목·닫기·Escape·초점 복귀가 있어야 한다.
- 이미지를 볼 수 없는 사용자에게 테마 이름과 톤 설명을 제공한다. 색상만으로 선택 상태를 구별시키지 않는다.
- ‘프롬프트 복사’와 ‘게임 제작’은 구분한다. 생성기 자체에서 HTML 게임을 만들었다고 안내하지 않는다.
- 도움말에는 코드로 받은 결과를 UTF-8·.html로 저장하는 절차와 전자칠판 창 이동을 설명한다.

학생 게임의 드래그 대안과 생성기의 좁은 화면 재배치는 [W3C Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html), [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)를 참고한다. 자동 시험만으로 전체 WCAG 적합성이나 교사 사용성 인증을 주장하지 않는다.

## 8. 구현·검증 범위

현재 시제품은 20개 장르, 12개 SVG 미리보기·확대, 설정 반영, 실제 프롬프트 조립, 복사·TXT, 반응형 배치를 구현했다. [자체 검증 보고서](self-verification-2026-09-10.md)에 브라우저 시험과 대비 결과를 기록했다.

시제품은 출시 제품 전체가 아니다. 조립기는 상세 조건을 지원하지만 화면에 노출하지 않은 진행 템포·소리·행동 선호 등이 있으며 초기화·수정 프롬프트 도우미는 후속 구현 범위다. 무료 ChatGPT 실제 생성, 20종 게임, 물리 전자칠판, 초보 교사의 관찰 평가는 별도다.
