# PRD·프롬프트·입력·디자인 자체 검증

검증일: 2026-09-10 / PRD 2.2·프롬프트 계약 1.1·디자인 명세 2.0 대응.

## 1. 수행 범위

문서 검토에 그치지 않고 순수 프롬프트 조립기, 독립 입력 상태 코드, 6인 입력 검증실, 실제 선택·복사·저장이 되는 디자인 시제품을 만들었다. 공개 자료는 공식 OpenAI 프롬프트 가이드와 Pointer Events·W3C 접근성 문서를 참고했다. 정식 생성기 전체, 무료 ChatGPT의 출력, 20종 완성 게임, 물리 전자칠판은 이번 자동 시험의 대상이 아니다.

## 2. 중요한 입력 사례

실제 Chromium이 전달한 `isTrusted` 포인터 이벤트로 6개 접점의 동시 존재를 확인했다. `isPrimary=false`인 나머지 손가락도 점수를 독립 처리했다. 이는 브라우저 자동화가 접점을 모사한 것이며 물리 터치 센서에서 온 입력은 아니다.

- 한 개인 영역에 두 손가락이 들어와도 다른 다섯 명의 조작을 막지 않는다.
- 다른 학생 구역에서 손을 떼면 소유권이 이관되지 않는다.
- 취소·일시정지·재시작·다음 문항 뒤 손 떼기로 이전 입력을 제출할 수 없다.
- 같은 완료 동작을 중복 호출해도 득점은 한 번만 적용된다.
- 마감 시각에서 입력이 거절되고 종료는 한 번만 확정된다.
- 마우스 포인터와 호환 click이 함께 발생해도 이중 득점하지 않는다.
- 한 학생의 완료 후 나머지 다섯 접점을 유지하는 사례는 추가 합성 DOM 이벤트로 검사했다. 이 사례는 CDP의 6개 동시 끌기 검사와 구분해 보고서에 표시했다.
- `next(owner, expectedRound, expectedRevision)`로 지연 콜백이 이전 문제에 속하는지 검사한다.

시작 전 준비·카운트다운, 실제 수학·다단계 퍼즐·팀 자원·공동 보스 진행은 참조 코드의 바깥 책임이다. 공통 코드가 통과해도 각각의 생성 게임에서 이벤트 연결·문항 판정·화면 유지가 제대로 통합됐는지 다시 시험해야 한다.

## 3. 검토 중 발견하여 수정한 항목

| 빈틈 | 조치 |
|---|---|
| 개인 구역만 분리하고 판/문항 구분 없음 | round + revision 토큰 도입, 늦은 손 떼기·콜백 차단 |
| 포인터 캡처의 event.target을 도착점으로 볼 위험 | 손 뗀 좌표의 실제 요소를 조회하도록 프롬프트·참조에 반영 |
| 모든 학생 DOM 재생성 위험 | 개인 구역만 갱신, 다른 학생 접점 보존 시험 |
| 첫 번째 포인터만 받는 구현 위험 | isPrimary 필터 금지·비주 접점 포함 시험 |
| 오답 보기 생성에는 재시도 상한이 없을 수 있음 | 문항과 보기 양쪽 생성 루프를 제한하도록 계약 수정 |
| 정답 예시만 정상이고 실제 출제 엔진은 다른 경우 | 교사 예시는 실제 생성 함수에서 만들도록 요구 |
| 입력을 선택할 때 초점 손실 | 게임 목록 DOM 유지, 선택 상태만 갱신 |
| 두 번째 자료만 지정하면 순서 표시 소실 | 범위 문자열에 첫째/둘째 자료 표지 유지 |
| Windows 줄바꿈과 textarea의 줄바꿈 방식 차이 | 조립 결과를 LF로 정규화해 미리보기·복사·TXT 내용 일치 |
| 첫 디자인의 어린이 대상 문체·교실 장식 | 중립적인 성인 교사용 문체·레이아웃으로 재설계 |
| 게임명과 짧은 설명만으로 행동 이해가 어려움 | 익숙한 장르명 + 학생 조작/게임 진행 설명 분리 |
| 색상 점만으로 테마 비교 불가 | 12개 고유 SVG 장면·확대 미리보기·톤 설명 |
| 초기 블록 테마의 작은 흰 글자 대비 4.47:1 | 색상을 수정했고, 최종 12개 테마는 새 팔레트로 재검사 |
| 큰 미리보기가 복사 버튼을 밀어냄 | 설정 요약·복사를 먼저 배치, 낮은 화면에서 고정 패널 해제 |

브라우저 시험의 첫 실행에서는 크기 변경 이벤트가 처리되기 전에 새 판을 시작하여 자동 일시정지 조건과 충돌했다. 크기 변경의 브라우저 프레임 처리를 기다리도록 시험을 수정했다. 이를 실제 학생 게임의 고장 수정이나 통과 사례 수 증가로 계산하지 않았다.

## 4. 프롬프트 고도화의 근거와 한계

필수 불변 조건만 고정하고 자료·수학·게임에 필요한 판단은 구체적인 결과 조건으로 요구했다. 선택 장르/테마만 포함하고 장황한 추론 출력·중간 PRD 승인·미사용 예시를 제외했다. 선택 테마의 배경·본문·카드·강조 색을 프롬프트에 함께 넣어 썸네일과 제작 요청의 연결을 강화했다.

[OpenAI 공식 추론 프롬프트 지침](https://developers.openai.com/api/docs/guides/reasoning-best-practices)은 명확한 지시·구분자·성공 조건을 사용하는 근거다. 해당 API 문서는 현재 무료 ChatGPT의 계정별 모델·파일 기능이나 이 작업의 실제 성공률을 확정하지 않는다.

[A안](example-prompt-coop-match.txt)은 계약 중심, [B안](example-prompt-coop-match-reference.txt)은 같은 조건에 시험한 공통 입력 상태 코드를 추가한 비교용이다. B는 코드 길이를 늘리고 모델 통합 부담이 생길 수 있으므로 검증 전 기본 출력으로 강제하지 않았다. A와 B의 실제 무료 생성 비교 결과는 없다.

## 5. 남은 실제 검증

| 항목 | 현재 상태 | 합격에 필요한 증거 |
|---|---|---|
| 무료 ChatGPT 첫 생성 성공률 | 미측정 | 무료 여부·화면 모드·동일 자료·새 대화 조건을 기록한 생성물과 실행 결과 |
| 임의 활동지 해석 | 샘플 연구와 판단 정책만 있음 | 제목 없는 자료·사진·혼합 2개·일부 쪽·모호한 조건의 실제 모델 결과 |
| 20개 장르의 실제 게임 | 미생성 | 각 장르의 자료 적합성·수학·핵심 행동·전체 설정 시험 |
| 물리 전자칠판 6인 | 미실시 | 실제 6명 동시 탭/끌기, 드라이버 접점 전달, 도달 높이·설 공간 확인 |
| Windows 복제·확장/DPI | 브라우저 크기 대응만 시험 | 실제 모니터 간 이동·배율·전체화면·터치 위치 매핑 확인 |
| 교사·학생 사용성 | 화면 검토·자동 조작만 수행 | 초보 교사의 독립 작업 수행과 학생의 이해·재참여 관찰 |

‘완벽’ 대신 실패를 발견하면 출시를 막는 기준을 사용한다. 수학 오류, 자유 답안, 필수 상단 터치, 순차 참여로의 자동 전환, 외부 실행 의존이 있으면 불합격이다. 최초 출력과 수정 후 결과를 구분하고 중요한 실패를 디자인 점수로 상쇄하지 않는다.

## 6. 재현 방법

번들 Node/Python과 Playwright가 있는 현재 환경에서 아래 파일을 실행한다. 배포되는 생성기 HTML은 이 런타임을 필요로 하지 않는다.

1. `scripts/build-prototypes.cjs`: 문서·카탈로그·스타일에서 단일 HTML과 프롬프트 예시 생성.
2. `scripts/verify-compiler.cjs`: 113,400 설정 조합과 예외 입력.
3. `scripts/verify-input.cjs`: 입력 상태 검사와 검증실 단일 HTML 생성.
4. `scripts/verify-browser.cjs`: Chromium 접점·하단 배치 시험.
5. `scripts/verify-design.cjs`: 생성기 선택·복사·이미지 미리보기·반응형 시험.
6. `scripts/verify-contrast.py`: 최종 색상 대비 검사.

원본 활동지와 킹수학 자료는 변경하지 않았다. 참조 입력 코드는 이번 작업에서 독립적으로 작성했다.

## 7. 프롬프트 1.2 자체 판단 및 하단 표시

약한 모델에 구현을 맡길 때 기존의 압축된 조건 나열만으로는 작업 순서와 입력 상태의 의미가 불명확하다고 판단했다. 기본 프롬프트에 구현 5단계, 충돌 시 우선순위, 문항 가족의 뜻과 구성 예시, 학생별 입력 처리 4단계, 관찰 가능한 완료 조건 7개를 추가했다. 선택/이동 중 임시 답안과 완료 후 채점을 구별한다. 내부 사고 과정 출력이나 중간 승인 요청은 요구하지 않는다. 전체 입력 참조 코드를 기본값에 추가하지 않고 필요한 구현 절차만 넣어 길이 증가를 제한했다.

재검증: 조립 113,400조합·예외 6그룹, 생성기 브라우저 14항목·6화면 폭, 입력 상태 16그룹·10,000순서 조합, 입력 브라우저 14항목·54배치를 통과했다. 입력 시험은 참조 구현에 대한 결과이며 앞으로 ChatGPT가 생성하는 모든 게임의 통과를 뜻하지 않는다. 무료 모델 성공률과 물리 터치 성능은 수치로 추정하지 않는다. 설계상 누락과 구현 해석의 여지를 줄인 개선으로 판단하며 실제 모델 성능 개선의 측정 결과로 표현하지 않는다.

생성기 본문 다음에 일반 흐름의 단일 푸터 `© 2026 찰떡쌤. All rights reserved.`를 추가했다. 생성 게임에 이 표기를 자동 삽입하는 조건은 추가하지 않았다.


## 8. 디자인 3.0 재검증

대표 장르 8개/전체 20개 펼치기, 선택 유지, 12색상 견본과 단일 장면 미리보기로 개편했다. 생성기 브라우저 검증 15항목, 6화면 폭, 색 대비 42쌍을 통과했다. 데스크톱 및 모바일 전체 화면 캡처를 직접 확인했다. 프롬프트 본문과 입력 참조 구현은 이번 디자인 변경에서 변경하지 않았다.

## 9. 수학 공작소·게임 테마 4.0

제품명을 수학 공작소로 통일하고 지정된 도입 문구를 반영했다. 12개 테마를 미션·탐험·아레나·팩토리·퀘스트 중심으로 교체하고 선택 버튼에 아이콘과 한 줄 경험을 추가했다. 큰 예시는 HUD·미션·진행 게이지·별·시간과 하단 개인 조작을 함께 보여 준다. 프롬프트 테마 계약에도 실제 진행 변화, 0.3~0.8초 반응, 단계 전환을 추가했다.

## 10. 패널·컬러 시스템 5.0

기존의 단일 대형 작업 패널을 3개의 단계 패널로 분리하고, 헤딩 배경·번호 배지·선택 상태에 초록/파랑/주황 계열을 일관되게 연결했다. 도입 패널, 선택 설명 보조 패널, 디자인 예시 보조 패널, 복사 패널만 추가하여 패널 중첩을 제한했다. 데스크톱·390px 전체 화면을 직접 확인했고 브라우저 16항목과 갱신한 생성기·테마 색 대비를 다시 검사했다.
