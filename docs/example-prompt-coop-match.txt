[문제 생성 절차와 독립 검산]
generateQuestion(유형, 난이도, 난수) → solveQuestion(원시 조건) → validateQuestion(문항) → 표시·채점으로 나누세요. solveQuestion은 생성기가 저장한 정답을 그대로 반환하지 않고 원시 조건으로 다시 풀어 교차 확인합니다. 화면에 적힌 식이나 문자열을 eval로 실행하지 마세요. 분수는 정수 분자·양의 분모와 최대공약수로 정규화하고, 소수는 필요한 자릿수의 정수 단위로 계산한 뒤 표시합니다.
검증은 수치 조건, 해 존재, 정답 개수, 보기 동치·중복, 단위, 그림의 수치 일치를 포함합니다. 보기의 위치·길이·색·고정된 문구로 정답이 드러나지 않게 하세요. 의도한 오개념으로 만든 오답도 실제 정답과 같아지면 버립니다. 정답이 여러 개인 연결·분류·조립은 특정 배치 한 개와 비교하지 말고 모든 조건의 충족 여부로 채점합니다.
유형·변형을 균형 있게 섞은 작은 출제 묶음을 소진 후 새로 섞고, 숫자와 보기 순서는 따로 생성하세요. 최근 12문항의 의미상 중복 키를 비교하되 가능한 문제 수가 적으면 기록 범위를 줄입니다. 경쟁에서는 동일 문항 순서 또는 검증된 같은 난도 분포를 쓰고, 무작위 장식·효과음이 출제 난수 순서를 바꾸지 않도록 난수 상태를 분리하세요.
교사 메뉴에 ‘문제 점검’을 넣어 유형×난이도별 최소 30개를 고정 난수로 검사하고 최소·최대값, 동치 분수, 경계 포함, 나머지 0 등 해당 경계 사례를 추가하세요. 실제 정답·그림·근거 생성 함수를 검사하며 오류 개수와 해당 문제를 보여 주세요. 순환 대기·무한 재시도를 막고 짧은 작업 단위로 나눠 화면을 멈추지 마세요. 통과 결과는 수학적 완전성 보증이 아니라 검사한 표본의 결과입니다.

[운영과 재미]
초기 진행은 공동 목표입니다. 다른 운영 방식도 게임 메뉴에서 바꿀 수 있게 구현하세요. 개인 도전은 자기 목표, 개인 대결은 동등한 조건의 개인 진행 비교, 팀전은 개인 조작을 유지한 팀 목표, 협동은 각자 기여가 공동 상태를 완성하는 방식입니다. 팀전 기본은 2팀 균등 배치이고 교사가 팀 구성을 변경합니다. 크기가 다른 팀은 유효 기여 합계를 팀 인원수로 나눠 비교하며 동점은 공동 순위입니다. 1인은 개인 목표로 전환합니다. 공동 목표량은 인원·시간에 맞추고 개인 순위를 표시하지 않습니다. 학생 한 명의 대기·오답은 다른 학생의 진행을 막지 않습니다.
문제 해결→눈에 보이는 변화→다음 수학적 선택으로 이어지게 하세요. 핵심 행동 하나와 이해하기 쉬운 보조 규칙 하나 이내로 구현하고 첫 화면에 한 문장 목표와 짧은 무점수 연습을 제공하세요. 정답 점수만 올리며 장르 이름을 붙이지 마세요. 경로/자원 선택·단계 변화·공동 건설 등 장르에 맞는 변화가 다음 선택에 영향을 주어야 합니다.
오답은 아래 확정 절차와 패널티를 반드시 적용합니다. 보기 전부를 연타해서 보상받을 수 없어야 합니다. 느린 학생을 탈락시키지 마세요. 협동에는 인원·시간에 맞는 공동 진행량과 끝 조건이 있어야 하며 개인 순위를 숨기는 것으로 대체하지 마세요. 한 학생 미응답이 전체를 무기한 막지 않게 하세요.

[오답 확정·패널티·정답 공개: 필수 구현]
학생별 문항 상태를 answering → gradedCorrect / gradedWrong → reviewing → next로 분리하세요. 제출 즉시 잠금을 동기적으로 걸고 정오답·첫 시도 여부를 저장한 뒤 점수/패널티를 한 번 반영하고, 그 다음에 화면·소리·풀이를 표시합니다. 채점 전에 힌트만 보여 주거나 오답을 미제출 상태로 되돌리지 마세요.
기본 규칙은 정답 +10점, 오답 −5점(최저 0점), 해당 학생 입력 1.2초 잠금입니다. 점수를 쓰지 않는 장르는 오답 시 해당 학생 행동 1.2초 잠금과 그 시도 진행/자원 보상 0을 반드시 적용하세요. 0점에서도 잠금은 적용되므로 무손실 연타는 불가능합니다. 패널티와 기준을 시작 화면에 한 줄로 안내하고 오답 때 실제 적용량(예: 3점에서 −3점 → 0점)과 남은 잠금을 표시하세요. 협동에서 공동 점수·다른 학생 자원을 빼거나 전체를 멈추지 마세요. 연습은 무점수이며 오답 판정과 잠금 흐름은 동일합니다.
오답 직후 해당 개인 구역에 ‘오답’이라는 판정을 문자·아이콘으로 먼저 표시하고, 그 아래 정답과 수학 근거 1~2문장을 보여 주세요. 기본은 풀이 확인 후 하단 ‘다음 문제’로 진행하며 빠르게 사라지는 자동 넘김으로 읽기를 방해하지 마세요. 공통 문항은 다른 학생의 정답을 노출하지 않도록 모두 제출하거나 라운드 마감 후 풀이를 공개하고, 먼저 제출한 학생에는 판정·패널티만 표시합니다.
재도전을 쓰는 경우에도 최초 오답 기록과 패널티를 유지하고 도움 뒤 같은 문항은 0점·진행 보상 0으로 처리하세요. 오답 판정 없이 힌트를 자동 노출하거나 힌트를 본 답에 정상 보상을 지급하지 마세요. 문제 자체의 도형·조건·퍼즐 단서는 유지하되 정답 유도용 도움은 판정 후에만 공개하세요.
드래그 취소·빈 곳 터치·미완성 배치·기억 카드 첫 장 열기 등 제출되지 않은 탐색은 오답이 아닙니다. 유효한 제출만 채점하고 잠금 중 연타·중복 이벤트는 패널티도 보상도 다시 적용하지 마세요. revision 변경 후에도 같은 원문항의 도움 사용 기록을 유지하세요. 일시정지 때 잠금의 남은 시간을 보존하고 재시작 때 이전 잠금 콜백을 폐기하세요.

[필수 애니메이션·이펙트·효과음]
효과 함수를 선언만 하지 말고 다음 실제 사건에 연결하세요. 채점은 먼저 한 번 확정하고 연출은 그 결과를 구독합니다.
- 선택: 해당 카드만 80~120ms 눌림 반응. 연결·조립은 붙을 대상 강조와 스냅 반응을 표시합니다.
- 정답: 해당 학생 구역에 체크·150~250ms 팝, 게임 대상까지 이어지는 빛/진행 게이지/자동 발사/조립 변화 중 장르에 맞는 300~600ms 반응, 120~250ms 상승 음정을 함께 제공합니다.
- 오답: 해당 학생 구역에 ‘오답’ 판정과 적용 패널티·작은 표식, 짧고 부드러운 낮은 음, 필요한 근거 한 줄을 표시합니다. 경고음 반복·전체 화면 흔들기·학생 공개 망신 연출은 쓰지 마세요.
- 공동 단계 달성: 게임 장면의 단계 전환과 400~800ms 배지·작은 별 입자, 구별되는 2~3음 효과음을 제공합니다. 협동은 개인 순위 대신 공동 기여가 모이는 연출을 씁니다.
- 시작·종료: 시작 신호와 종료 팡파르를 구별하고, 종료 때만 0.8~1.2초의 짧은 축하 연출을 제공합니다. 시간 종료 자체를 실패로 단정하지 마세요.
외부 음원 없이 Web Audio의 OscillatorNode와 GainNode로 효과음을 구현하세요. AudioContext 하나와 전체 음량을 공유하고 교사의 시작/소리 켜기 동작에서 생성·resume합니다. 기본 음량은 낮게, 교사 메뉴에 효과음 켜기/끄기·음량·소리 확인을 둡니다. 시작 기본값은 효과음 켬으로 고정하며 생성기에 소리 선택 항목을 요구하지 마세요. 짧은 attack/release로 클릭 잡음을 줄이고 음원 노드는 종료 후 정리합니다. 자동 재생 거부·오디오 실패 시 무음으로 플레이를 계속합니다.
6명 동시 정답에는 시각 반응을 각자 유지하되 같은 종류 소리는 80ms 안에서 합치고 동시 음원은 4개 이하로 제한하세요. 종료·단계 신호를 개별 정답음보다 우선하고 밀린 소리를 뒤늦게 재생하지 마세요. 반복 배경 음악은 기본 끔이며 필수 효과음보다 우선하지 않습니다.
효과 레이어는 pointer-events:none이며 버튼 위치·폭·높이를 바꾸지 않습니다. 움직임은 transform/opacity 위주로 처리하고 동시에 살아 있는 입자는 화면 전체 48개 이하로 제한합니다. 한 학생 연출이 다른 학생의 터치나 문제 진행을 막으면 안 됩니다. 일시정지·탭 숨김은 시각 효과·소리를 함께 멈추고 재시작·종료에서 예약 작업을 정리합니다. 움직임은 matchMedia의 prefers-reduced-motion 기기 설정을 따르고 변경도 반영하세요. 생성기에 움직임 선택 항목을 요구하지 마세요. 움직임 줄이기에서는 이동·확대·입자를 정적인 체크·게이지 변화로 대체하며 피드백을 없애지 마세요.

[학생 화면의 정보량과 편의성]
플레이 화면은 상단에 짧은 목표·시간·진행 지표 하나, 하단 개인 구역에 학생/팀 표시·현재 문제·필요한 응답과 도움만 표시하세요. 점수·정답 수·콤보·진행률을 같은 의미로 중복 나열하지 마세요. 짧은 반응과 움직임으로 진행을 알리고 장문 상태 메시지는 줄입니다. 문장이 짧아도 판정에 필요한 조건·단위·부정어는 삭제하지 않습니다.
공통 문제는 상단에 한 번, 서로 다른 문제는 해당 학생 하단 구역에 표시합니다. 상단 장면과 하단 조작이 어떤 관계인지 번호·같은 도형으로 연결하되 정답을 색으로 암시하지 마세요. 반응은 한 곳에 표시하고 정오답으로 모달을 매번 열지 마세요. 근거가 길면 오답 확정 뒤 풀이 단계로 나누고 교사 검토에서 전체 풀이를 보여 줍니다.
학년 추론·자료 출처·유형명·난이도 규칙·검사 결과·설정 설명은 교사 메뉴에 모으세요. 시작 화면은 목표 한 문장과 시작 버튼을 중심으로, 결과 화면은 목표 달성/진행 정도·핵심 기록 하나·다시 하기를 중심으로 구성합니다. 도움은 필요할 때 열고 닫으며 같은 설정으로 재시작할 수 있어야 합니다. 교사 설정은 실수 터치를 피하도록 별도 메뉴에 둡니다.

[하단 조작·다중 터치]
상단의 문제·경주장·보스·큰 그림은 보기 전용입니다. 모든 학생 터치 대상의 전체 경계, 드래그 시작점/도착점, 확인/취소/힌트를 하단 개인 구역에 두세요. 상단 상태는 하단 카드·축소 조작판으로 조작합니다.
조작 영역의 위쪽 경계는 기본 화면 높이 65%, 교사 조절 60~80%로 설정하세요. 1~6개 개인 구역은 하단 가로 배치하고 학생을 상하 2줄로 배치하지 마세요. 주요 터치 대상 최소 64 CSS px와 간격 8 CSS px를 확보하세요. 개인 구역 내부 카드 2열 배치·과제 단계 분할은 가능합니다. 장식과 동시 카드 수부터 줄이고 스크롤·지나친 글자 축소·상단 이동으로 해결하지 마세요. 1280×720, 1366×768, 1920×1080에서 검토하고 물리 설치 높이는 교사가 시작 전 확인하게 하세요.
Pointer Events로 학생별 답안·진행·채점 잠금을 분리하세요. isPrimary만 허용하는 필터는 쓰지 마세요. 누른 개인 구역과 판 ID·문항 revision에 pointerId를 묶고 다른 구역으로 넘어가도 이관하지 마세요. 손을 뗄 때 좌표의 실제 대상을 확인하고 판/문항이 바뀌었으면 무시하세요. 포인터 캡처 중 event.target이 도착 칸이라고 가정하지 마세요. pointercancel·lostpointercapture·손 떼기·영역 이탈을 정리하고 개인 구역의 중복 동작을 막으세요. pointer와 click/touch 이벤트로 같은 행동을 이중 채점하지 마세요. touch-action은 학생 영역에 적용하고 교사 메뉴 스크롤은 보존하세요. 한 학생 피드백으로 다른 학생 영역 DOM을 교체하거나 포인터를 취소하지 마세요.
Windows 복제·확장에서 한 게임 창을 사용하세요. 현재 요소 경계와 표시 배율로 좌표를 계산하고 canvas 표시 크기와 그리기 해상도를 구분하세요. 창 이동·크기 변경·전체화면·배율 변화에 맞춰 갱신하세요. 높이/레이아웃 변경은 일시정지하고 진행 포인터를 정리한 뒤 적용하세요. 전체화면 실패 시 일반 창도 동작해야 합니다. 시작 전 개인 영역별 터치 확인을 제공하되 물리 기기의 동시 터치 수나 Windows 연결을 HTML이 보장·수정한다고 하지 마세요.

[입력 구현 절차]
판 ID는 새 게임마다 증가하는 번호, revision은 해당 학생의 문제가 바뀔 때 증가하는 번호입니다. 전체 게임의 phase·판 ID, 학생별 question·revision·선택·잠금·점수, pointerId별 소유 학생·판 ID·revision을 따로 보관하세요. 학생 번호가 손가락 번호라고 가정하지 마세요.
① pointerdown: 누른 학생 구역을 소유자로 기록하고 해당 요소에 포인터 캡처를 설정합니다. 같은 학생의 두 번째 손가락만 무시하며 다른 학생 입력은 계속 받습니다.
② pointerup: clientX/clientY로 document.elementFromPoint의 실제 도착 대상을 찾습니다. 같은 학생 구역·같은 판·같은 문항·플레이 중·마감 전일 때만 처리하고 포인터 기록을 정리합니다.
③ 채점: 카드 선택·이동은 학생별 임시 답안에 반영하고 완성/확인 조건에서만 채점합니다. 현재 문항의 잠금을 먼저 걸고 보상을 한 번 반영한 다음 해당 학생의 화면만 갱신합니다. 다음 문항에서 revision을 증가시키고 잠금을 풉니다. 오답 재도전을 허용할 때도 이전 입력이 재사용되지 않게 revision을 증가시킵니다.
④ 취소: pointercancel·lostpointercapture는 그 손가락의 미완료 동작만 지웁니다. 일시정지·재시작은 전체 입력을 정리합니다. 손 떼기 후 캡처 해제 알림으로 이미 확정한 답을 취소하지 마세요.
단순 선택과 ‘카드 탭→대상 탭’도 이 흐름으로 처리하세요. 연결 중 선택은 학생별로 보관하고 취소된 손동작으로 답을 확정하지 마세요. 전역 입력 잠금 하나로 여섯 명을 묶지 마세요.

[상태·설정]
준비→연습/카운트다운→플레이→일시정지/결과를 구분하고 플레이 중에만 채점하세요. 단조 증가 시각으로 실제 남은 시간을 계산하고 일시정지·탭 숨김에는 시간과 움직임을 함께 멈추세요. 복귀 후 교사가 이어가게 하세요. 마감 시각 이후 입력은 거부하고 결과는 한 번만 확정하며 종료 때 미응답은 오답으로 세지 마세요.
