# 단일 HTML 프롬프트 생성기 상세 설계

버전 1.1 / 2026-09-10 / PRD 2.2 기준. 구현 계약과 자체 시험용 조립기·입력 참조 코드를 함께 관리한다. 실제 통과 범위는 [자체 검증 보고서](self-verification-2026-09-10.md)를 따른다.

## 1. 책임 경계

| 구성 | 수행 | 수행하지 않는 일 |
|---|---|---|
| 생성기 HTML | 선택·설명·정적 조합 검사·프롬프트 조립·복사·TXT 저장 | 자료 업로드·OCR·LLM·학년 추정·자료 적합성 판정 |
| 프롬프트를 받은 ChatGPT | 첨부 이해·목표 추론·문항 생성 규칙 설계·게임 HTML 작성 | 모르는 자료를 읽었다고 주장·물리 보드 시험 통과 주장 |
| 생성된 게임 HTML | 수학 규칙에서 새 문제 생성·동시 입력·판정·게임 상태·교사 설정 | 새 활동지 분석·온라인 문제 생성·학생 키 자동 측정 |

일반화의 단위는 출판사·단원 번호가 아니라 수학 목표와 불변 조건이다. 임의 자료 전체를 유한 게임으로 항상 보존할 수 있다는 전제를 두지 않는다. 중요한 모호성만 질문하는 경로는 정상 제품 흐름이다. 장르와 자료의 결합 가능성은 첨부를 실제로 본 단계에서 결정한다.

## 2. 단일 파일 안의 논리 구분

`CONFIG_SCHEMA → GAME_CATALOG / THEME_CATALOG / MODE_RULES → normalize → resolve → compile → validate → UI`

- HTML/CSS와 일반 script를 파일 안에 포함한다. 소스 조직을 나누되 외부 모듈 import를 요구하지 않는다.
- 설정 객체가 유일한 선택 상태다. 카드 클릭·요약·복사 결과가 서로 다른 값을 기억하지 않는다.
- 카탈로그는 데이터, 조립기는 순수 함수, UI는 표시와 이벤트를 담당한다.
- 내부 ID를 화면 이름으로 대체하지 않는다. 표시 이름 변경 시 설정 호환성을 유지한다.
- `schemaVersion`, `catalogVersion`, `promptVersion`을 분리한다. 설정 저장은 버전을 포함하고 버전이 다른 가져오기는 명시된 마이그레이션만 허용한다. 알 수 없는 필드를 코드로 실행하지 않는다.
- 생성기에는 학습 자료·학생 이름 저장이 필요 없다. 학생은 번호·색·기호로 구별한다.

## 3. 설정 스키마

| 필드 | 값·기본값 | 역할 |
|---|---|---|
| gameId | 20개 ID 또는 novel; 기본 quiz | 생성할 장르 하나 |
| themeId | PRD의 12개 ID; 기본 classroom | 디자인 계약 하나 |
| players | 정수 1~6; 기본 2 | 시작 동시 인원 |
| durationSec | 45/60/90/120 또는 null; 기본 60 | null은 무제한, 0과 구분 |
| mathLevel | low/mid/high; 기본 mid | 자료 기준 수학 난이도 |
| mode | auto/solo/versus/teams/coop; 기본 auto | 장르 추천 또는 교사 지정 |
| grade | null 또는 1~6; 기본 null | null은 자료 수준 유지, 가짜 학년 추정 금지 |
| pace | relaxed/normal; 기본 normal | 여유와 연출 템포, 반사 능력 평가 아님 |
| actionPreference | auto/choice/connect/sort/order/construct; 기본 auto | 허용 행동 선호. 장르와 충돌 시 이유 표시 |
| sourceScopes | 파일을 구별할 이름·쪽 종류·범위·제외 내용 최대 2개 | 선택 사항, 실제 업로드 아님 |
| learningGoal | 선택 문자열 | 교사가 지정할 때만 범위 판단에 사용 |
| customIdea | 선택 문자열 | 선택 장르 세부 아이디어 또는 novel 조건 |
| feedback | hintRetry/explainNext; 기본 explainNext | 오답 다음 행동 |
| reachTopPct | 60~80, 기본 65 | 학생 조작 영역의 위쪽 경계 |
| sound | 기본 false | 시작 소리 |
| reducedMotion | 시스템 선호 또는 교사 선택 | 시각 연출만 축소 |

텍스트 길이 제한은 입력 시 알리고 초과 문장을 몰래 자르지 않는다. 상세 필드는 접어 두고 기본 화면은 게임·디자인·난이도·시간·인원 중심으로 구성한다. 운영 방식은 추천을 바로 볼 수 있고 한 번 눌러 변경할 수 있다. 학년이나 단원명을 필수 입력으로 만들지 않는다.

수업 범위는 ‘전체/일부’와 파일 구별·쪽 종류·문항 입력을 제공한다. 자료 파일명은 선택 입력이며 붙여넣을 때 첨부 이름과 맞추도록 안내한다. 실제 첨부 여부를 알 수 없으므로 ‘첨부 확인 완료’ 표시를 만들지 않는다.

## 4. 조합 결정과 우선순위

고정 원칙: 수학 정확성·자료 목표 보존, 자유 답안 금지, 수학 판단 중심, 하단 전체 조작, 1~6인 동시 참여, 오프라인 단일 파일. 사용자 정의 아이디어도 이 원칙 안에서 해석한다.

1. 숫자 범위·enum·문자열 형식을 정규화한다. 알 수 없는 장르·테마를 기존 ID로 오인하지 않는다.
2. 교사가 명시한 설정과 추천값을 구분한다. `auto`만 장르 추천으로 해결한다.
3. 1인+팀/개인 대결은 개인 목표로 해석하고 화면 요약에 알린다. 1인 협동은 혼자 공동 목표를 수행하는 개인 도전이다.
4. 장르와 행동 선호가 정적으로 충돌하면 조용히 무시하지 않는다. 예: 카드 뒤집기+순서 강제는 ‘이 게임은 카드 선택으로 진행’이라고 표시하고 사용 가능한 행동을 고르게 한다. 기본 auto는 막힘 없이 동작한다.
5. 자료 적합성·학년 수준은 결정하지 않는다. 이를 ChatGPT가 분석하도록 본문을 포함한다.
6. 자유 입력에 명백한 금지 요구가 있으면 해당 제품 원칙을 옆에 안내한다. 키워드만으로 안전성·의미를 완전히 판정했다고 하지 않는다. 복사 본문에서도 자유 아이디어를 조건 데이터로 구분하고 고정 원칙 안에서 해석하게 한다.
7. 확정된 초기 운영과 선택 장르의 모든 런타임 운영 변환 규칙을 함께 조립한다. 게임 안에서 운영 방식을 바꿀 수 있으므로 초기 모드만 구현하라는 프롬프트를 내보내지 않는다.

프롬프트 블록 순서는 목표→정규화한 설정→고정 원칙→자료 이해→변형→출제/판정→선택 장르→운영/재미→하단/입력→상태/설정→테마/파일→교사 검토→출력이다. 같은 선택은 같은 문자열을 만든다. 날짜·무작위 문구를 자동 삽입하지 않는다.

검사 실패 시 잘못된 결과를 복사했다고 표시하지 않고 문제 필드를 가리킨다. 프롬프트를 직접 수정할 수 있게 할 경우 ‘직접 수정본’으로 구별하고 설정 변경으로 덮어쓸 때 안내한다. 기본 흐름은 읽기 전용 미리보기다.

## 5. 장르 카탈로그 계약

각 항목에는 `id, label, actionSummary, compatibleActions, defaultMode, questionFlow, coreRule, invalidAction, progressRule, endRule, tieRule, modeAdapters, layoutStrategy`가 필요하다. 이름·이미지만 존재하는 장르 항목은 출시하지 않는다.

아래는 각 항목의 최소 행동·진행 계약이다. 개별 보상량은 실제 생성 게임이 인원·시간·자료 난도에 맞춰 정하고 교사 검토에 목표를 표시한다. 모든 조작은 하단이며 ‘지도 선택’도 하단 대상 카드나 조작판을 의미한다.

| ID | 다른 장르와 구별되는 수학 행동·진행 | 잘못된 행동·끝 조건 |
|---|---|---|
| quiz | 공통 과제에서 맞는 보기/집합 판단. 각자 응답 후 다음 라운드, 첫 판단과 도움 뒤 해결 구별 | 한 라운드 보상 1회, 모두 응답 또는 라운드 한도 후 이동; 시간/정한 라운드 종료 |
| race | 조건·비용이 다른 길 중 수학적으로 유효한 경로 선택. 선택 결과가 거리·다음 갈림길에 반영 | 불가 경로는 단서 후 재선택, 목표 거리 또는 시간 종료 |
| tug | 수학적으로 얻은 힘을 적용할 구간/배분 선택. 상대 또는 공동 목표와 힘이 합산·상쇄 | 무효 배분은 적용 안 함, 목표선 또는 시간의 진행량으로 종료 |
| boss | 공격·보호 등 현재 단계에 필요한 수학 자원/관계 선택. 단계 변화로 다음 판단 조건 변경 | 자원 중복 사용 금지, 공동 단계 완료 또는 시간 종료 |
| defense | 위협 조건을 읽고 맞는 방어 수단/위치 배치. 배치 뒤 웨이브가 자동 진행 | 잘못된 대응은 수학 근거 제공, 탈락 없이 회복 가능; 웨이브/시간 종료 |
| target | 한 조건에 해당하는 여러 표적을 판별·선택 후 자동 발사, 조건별 세트 완성 | 틀린 표적 선택은 근거 제시, 탄막·수동 조준 없음; 세트/시간 종료 |
| bingo | 문항에 대응하는 자기 판 칸 선택, 어떤 줄을 완성할지 공간 상태를 고려 | 같은 칸 재보상 금지, 복수 유효 칸 처리 명시; 줄 목표/시간 종료 |
| match | 공개된 식·값·그림 사이의 수학 관계를 연결해 그래프/짝 완성 | 끊기·재연결 허용, 동치 다중 연결은 조건대로 인정; 세트/시간 종료 |
| memory | 숨긴 카드 두 장의 수학 관계 확인, 기억한 위치를 이용해 대응 제거 | 불일치 잠깐 공개 후 닫음, 다른 학생에게 잠금 전파 없음; 세트/시간 종료 |
| sort | 항목을 조건별 구역으로 분류, 올바르게 처리한 묶음이 공정 단계를 완성 | 경계·중복 소속 정책 명시, 잘못 분류한 항목에 근거; 묶음/시간 종료 |
| path | 인접과 수학 통과 조건을 함께 만족하는 다음 칸을 선택하며 출구 탐색 | 벽·비인접 이동 거부, 막힘 시 되돌리기, 유효 경로 존재; 출구/시간 종료 |
| sequence | 이미 주어진 유한 집합을 수학 조건에 맞게 재배열 | 일부 교환·되돌림 가능, 여러 유효 순서 인정; 배열 세트/시간 종료 |
| build | 주어진 도형·분수 조각을 결합해 목표량/형태 구성 | 넓은 스냅·되돌림, 겹침/분할 제약 판정; 구성 세트/시간 종료 |
| merge | 수학적으로 결합 가능한 타일을 골라 새 타일로 변환, 변환 후 가능한 선택도 변경 | 유효 쌍 없는 상태 검사·재구성, 자료에 없는 2048 규칙 강제 금지; 목표 타일/시간 종료 |
| territory | 수학 조건을 만족하는 인접 후보를 골라 영역 확장 | 공유 대상 충돌 처리와 권한 환급, 불가 칸 거부; 점유 목표/시간 종료 |
| balance | 고정된 추·수량 조각을 선택해 양쪽 등량/등식을 구성 | 음수 재고·동시 중복 사용 방지, 여러 해 인정; 균형 과제/시간 종료 |
| estimate | 근삿값·수직선 구간을 선택해 목표가 있는 범위를 좁힘 | 정확값/허용 구간을 수학적으로 구분, 손 위치 오차 채점 없음; 범위 목표/시간 종료 |
| rhythm | 반복·변화 규칙으로 다음 항/블록을 선택해 새 패턴 생성, 완성 뒤 시각/소리로 재생 | 정해진 박자 입력 없음, 단순 정렬과 구분; 패턴 길이/시간 종료 |
| resource | 예산·재고·주문 관계를 판단해 정해진 물품/묶음 선택, 잔량이 다음 선택에 영향 | 초과 구매·재고 음수 거부, 숫자 키패드 없음; 주문 목표/시간 종료 |
| code | 수학 단서를 적용해 후보를 제거하고 일치하는 후보 선택 | 단서와 실제 후보 집합 일치, 유일 해 또는 복수 해 규칙 명시; 사건/시간 종료 |

공통 지연 규칙: 카드 공개·틀림 피드백 등은 해당 학생에게만 적용한다. 동기 라운드 종료 대기는 제한 시간을 가지며 전체 한 판 시간을 넘기지 않는다. 비동기 경쟁은 같은 문항 순서 또는 같은 난도 분포를 사용하고 숨은 개인별 난도 변경을 하지 않는다.

장르 적합성: 분수 곱셈에 블록 합치기을 결합하면 곱셈 관계로 타일 결합을 설계할 수 있는지 판단해야 한다. 불가능하면 장르 이름만 유지한 다른 수학으로 바꾸지 않는다. 새 게임은 동일한 계약 필드를 모델이 채우되 후보 나열로 멈추지 않는다.

## 6. 운영 모드 계약

| 모드 | 진행과 결과 | 설정·공정성 |
|---|---|---|
| 개인 도전 | 각자 장르 목표·개인 진행 표시, 개인 기록/완성 | 다른 학생 순위 필수 아님 |
| 개인 대결 | 동등한 과제 조건과 진행 지표로 비교 | 같은 점수는 공동 순위, 손가락 속도로 동점 해소하지 않음 |
| 팀 대결 | 개인 동시 과제→팀 진행 합산, 장르 목표로 비교 | 교사가 팀 구성 변경. 기본 2팀에 균등 배치, 2명 이상부터 팀전 |
| 공동 목표 | 개인 동시 기여→공동 건설/수집/방어/탐사 진행, 공동 끝 조건 | 개인 순위 없음. 참가 인원·판 시간에 목표량 조정, 한 사람 실패로 즉시 전체 실패 없음 |

홀수 팀은 단순 총점을 그대로 비교하지 않는다. 개인 유효 기여를 팀 인원수로 나눈 값으로 비교하고 학생 화면에는 이해하기 쉬운 진행 막대를 표시한다. 비경쟁 협동에는 경쟁용 인원 보정을 불필요하게 적용하지 않는다. 게임 목표량에 필요한 참가 인원을 반영한다.

장르별 `modeAdapters`는 같은 수학 행동을 유지하면서 대상을 바꾼다.

- 공유 대상이 있는 race/tug/boss/defense/territory: 개인 모드는 개인 또는 각 진영 대상, 팀전은 팀 대상, 협동은 공동 경로/목표선/보스/성/지도. 개인 모드 보스는 각자 단계 목표를 가진다.
- 개인 판을 완성하는 bingo/match/memory/path/sequence/build/merge/balance/estimate/rhythm/code: 개인 판은 계속 분리하고 완료가 개인 기록·팀 진행·공동 완성량 중 어디로 반영되는지 바꾼다. 협동에서는 판 완성이 공통 퍼즐/작품의 일부를 실제로 완성하고 그 상태를 보여준다.
- 항목을 처리하는 quiz/target/sort/resource: 개인 판단은 분리하고 묶음 완료가 개인·팀·공동 주문/수집 목표로 반영된다. 협동도 다음 공동 단계와 완료 조건을 갖는다.

팀전에서도 한 명씩 교대하거나 팀당 입력창 하나를 공유하지 않는다. 역할이 필요하면 개별 학생에게 계속 수행 가능한 일을 제공하고 1인은 역할을 자동 통합한다. 영토 공유 충돌은 같은 처리 묶음의 요청 중 추첨하고 미선택자에게 권한을 돌려준다. 이 중재 추첨을 수학 정답/오답으로 표시하지 않는다.

## 7. 자료에서 게임까지의 중간 구조

ChatGPT가 작성할 게임에서 다음 책임을 구분하도록 프롬프트에 결과 조건으로 요구한다. 교사에게 JSON을 직접 작성시키거나 중간 PRD 승인을 강제하지 않는다.

```text
SourceProfile
  confirmedMetadata / inferredSkills / unresolvedCritical
  selectedScopes / usedFamilies / transformedFamilies / excludedWithReasons
FamilySpec
  sourceRefs / objective / numberDomain / variables / invariants
  levelProfiles / allowedAction / generate / validate / fallback
Question
  familyId / canonicalKey / values / presentation / targets
  solutionRule / explanation / attemptState
GameState
  roundId / phase / deadline / pauseState / players / teams / sharedGoal
```

이 이름은 설계 설명이며 모델에게 같은 함수명을 무조건 강제할 필요는 없다. 중요한 것은 자료 해석, 수학 값, 화면 표현, 채점, 게임 보상을 섞지 않는 것이다. 학생이 카드를 옮겨 새 수학 상태를 만들면 같은 상태에서 정답과 그림을 다시 계산한다.

객관식 품질 기준: 정답 위치 균형, 오개념 근거, 값/표현 동치 처리, 너무 눈에 띄는 길이·색 단서 방지, 복수 선택의 제출 시점, 보상 중복 방지. 자유 입력을 없앴다고 계산 정확성 검사가 사라지는 것은 아니다.

## 8. 하단 배치 계약

- `touchBandTop = viewportHeight × reachTopPct / 100`. 터치 대상의 전체 사각형이 이 경계 아래이며 개인 구역 폭 안에 있어야 한다.
- 6인도 가로 6구역이다. 학생을 위아래 줄로 나누지 않는다. 문제 설명은 상단에서 볼 수 있지만 답을 읽기 위해 학생이 장식이나 긴 지문을 찾아 헤매지 않게 한다. 가능한 짧은 과제는 하단에도 함께 표시한다.
- 연결 양 끝, 조립판, 재료, 카드 넘김·확정·도움 모두 같은 하단 개인 구역에 둔다. 상단 큰 상태는 조작하지 않는 복제 표시다.
- 64 CSS px와 8 CSS px는 설계 초깃값이다. 6인·1280px 폭에서 복잡한 카드판을 그대로 축소하지 않는다. 카드 수/동시 정보량 감소, 순차 단계 분할, 선택→대상 탭으로 조작 범위를 줄인다. 단계 분할은 개인 안에서 이뤄지고 다른 학생은 동시에 진행한다.
- 높이 80% 설정처럼 좁은 띠에서는 한 번에 표시할 행동 수를 줄인다. 화면 치수상 최소 표적을 보존할 수 없다면 교사에게 더 넓은 창/화면 맞춤을 안내한다. 지원 기준 화면에서도 불가능하면 해당 장르 구현은 실패다. 위쪽 터치나 순차 참여를 자동 대안으로 쓰지 않는다.
- 물리 도달 높이, 여섯 명이 설 공간, 실제 터치 지원은 CSS 크기에서 추론할 수 없다. 터치 확인에서 학생 구역별 눌린 표시와 동시 접점 상태를 보여주며 모든 보드가 6점을 보낸다고 가정하지 않는다.

## 9. 흥미 수용 기준

재미는 이펙트 개수가 아니라 반복하고 싶은 수학 선택과 진행으로 평가한다.

1. 10~15초의 무점수 연습에서 학생이 무엇을 해야 하는지 이해할 수 있는가? 시간은 설계 목표이며 아직 측정하지 않았다.
2. 같은 수학 판단이라도 숫자·표현·관계·목표 상태가 바뀌어 다음 과제의 판단이 필요한가?
3. 장르의 선택이 경로·자원·공간·단계에 실제로 영향을 주는가?
4. 오답 뒤 다시 참여할 길이 있고 임의 연타는 유리하지 않은가?
5. 협동에서 공동 상태의 변화와 각자 할 일이 보이는가?
6. 정답을 맞혀도 긴 연출 때문에 다음 행동이 막히지 않는가? 소리·움직임을 줄여도 진행이 이해되는가?

랜덤 효과가 정오답 판정을 바꾸지 않는다. 무작위 승패 보상이 수학 기여를 뒤집지 않게 한다. 제한 시간 종료는 순위 발표만 있는 결과로 고정하지 않고 모드에 맞춰 공동 완성·도전 결과·다음 목표를 보여준다.

## 10. 생성기 편의·출력 검사

- 기본 흐름은 ‘고르기 → 프롬프트 복사 → ChatGPT에 자료 1~2개와 함께 붙이기 → HTML 열기’다.
- 마지막 요약은 초기 조건과 고정 원칙을 함께 보여준다. 예: ‘4명 · 협동 · 90초 · 하단에서 잇기 · 자료에 맞춰 문제 변형’.
- 복사는 성공한 경우만 완료 표시. Clipboard API 실패 시 전체 선택·수동 복사와 TXT 저장 제공.
- 로컬 설정 저장이 거부돼도 사용 가능. 옵션 내보내기/가져오기는 후속 편의 기능이며 프롬프트 생성에 필수 아님.
- 화면 설명에는 실제 ChatGPT의 첨부·모드 선택 명칭을 특정 버전에 고정하지 않는다. 자료를 볼 수 없는 상황에서 생성기가 이를 해결했다고 하지 않는다.
- `compile` 결과에는 필수 블록 1회씩, 선택 장르 1개, 테마 1개, 전체 런타임 운영 변환, 모든 설정 필드 반영이 필요하다.
- 미치환 변수, undefined/null 문자열 누출(무제한은 자연어로 변환), 상충된 설정 문장, 필수 블록 중복을 검사한다. HTML 화면에 교사 자유 텍스트를 표시할 때는 텍스트로 렌더링한다.
- 글자 수는 정보로 제공하고 긴 경우 먼저 선택하지 않은 설명·중복을 줄인다. 필수 규칙이나 교사 범위를 몰래 잘라 길이를 맞추지 않는다.

## 11. 검증 계획과 출시 관문

다음은 전체 제품의 시험 범위다. 조립기와 입력·디자인 시제품의 실행 결과는 [자체 검증 보고서](self-verification-2026-09-10.md)에 있고, 생성 게임과 물리 보드 시험은 아직 남아 있다.

| 단계 | 사례·합격 조건 |
|---|---|
| 조립기 정적 조합 | 20장르+novel × 12테마 × 3난도 × 5시간 × 6인원 × 5운영 = 113,400개 조합에서 결정성·필수 필드·유효한 모드 정규화·변수 누락 검사. 이 수는 게임 품질 시험 수가 아님 |
| 예외 설정 | 자유 입력·범위 지정 2개·복사 실패·저장 거부·알 수 없는 ID·1인 팀전·행동 충돌·높이 경계 검사 |
| 자료 일반화 | 제목/학년 없는 연산, 사진 분수, 단위/도형, 표/그래프, 원리 설명형, 서로 다른 단원 2개, 문제지+해설, 핵심 판독 불가, 지정 일부 쪽. 정상 제작과 필요한 질문을 각각 판정 |
| 독립 수학 검사 | 각 생성 가족×난도마다 경계와 여러 시드 표본 검사, 정답·보기·그림·근거 일치. 같은 함수 출력만 다시 비교하지 않음 |
| 무료 실제 생성 | 20개 장르 각각 최소 1개 적합 자료로 첫 출력부터 실행, 이 중 대표 6개는 다른 새 대화로 3회 반복하여 우연한 성공 구분 |
| 화면·상태 | 1~6명과 모든 운영 방식, 3개 기준 해상도, 높이 60/65/80%, 하단 경계·표적 크기·재시작·일시정지·설정 적용·시간 종료 검사 |
| 물리 전자칠판 | 실제 6명 동시 탭/끌기, 구역 간 이탈·취소·양손 연타, 화면 복제/확장·배율·전체화면, 작은 학생 도달과 공간 확인 |
| 초보 교사·학생 | 설명 없이 복사·첨부·저장·열기 가능한지 관찰, 한 문장 목표 이해와 실제 장르 차이·재참여 의향 기록 |

출시 표시에 필요한 관문: 알려진 수학 오류 0, 자유 입력 0, 상단 필수 터치 0, 동시 참여의 순차 전환 0, 외부 실행 의존 0, 장르별 고유 행동 존재. 최초 완성률과 수정 후 완성률을 분리해 공개한다. 위반이 발견되면 해당 사례는 실패로 기록하고 수정 후 재검증한다. ‘모든 미지의 자료에서 완벽’이나 ‘앞으로 리팩토링 불필요’는 검증 가능한 약속으로 쓰지 않는다.

## 13. 검증용 구현과 제품 구현의 관계

`prototypes/compiler.js`는 정규화·조립·오류 처리를 구현했고 `catalog.json`은 20개 장르+novel과 12개 테마를 보관한다. 현재 카탈로그는 PRD 표를 읽는 빌드 스크립트로 생성한다. 출시 구현에서는 JSON을 편집 원본으로 승격하고 문서와 대조하되 ID·입출력 계약을 유지한다. 카탈로그 필드는 시제품에서 일부 합쳐져 있고 최종 확장 필드의 의미는 5절을 따른다.

프롬프트 본문은 `prompt-contract-draft.md` 첫 text 블록이 원본이다. 빌드 스크립트가 실제 조립기에 넣고 단일 HTML 안에 인라인으로 포함한다. 교사 텍스트는 조립 후 재치환하지 않고, HTML에는 안전하게 직렬화하거나 textContent/value로 표시한다. UI 범위 문자열은 첫째/둘째 자료 표지를 유지한다.

입력 참조의 책임은 포인터 소유권·판/문항 세대·중복 제출·시간/일시정지다. DOM 좌표 판정·캡처·선택 상태·수학 판정은 게임 어댑터 책임이다. 따라서 참조 코드만 복사했다고 완성 게임을 검증했다고 하지 않는다. 해당 분리는 프롬프트 B안의 통합 안내에도 명시한다.

디자인과 실제 화면 규칙은 [디자인 명세](generator-design-spec.md)를 따른다. 생성기 내부에 자료 분석 능력이나 모델 실행 결과가 있는 것처럼 표시하지 않는다.

디자인 데이터에는 배경·본문·카드·강조·보조 글자 색을 포함한다. `theme-art.js`는 12개 인라인 SVG 예시를 만들고 선택 팔레트는 제작 프롬프트에도 들어간다. `genre-copy.json`은 성인 교사용 학생 조작·진행 설명을 별도로 관리하며 20개 ID와 일치해야 한다. 명명·이미지·문체의 기준은 디자인 명세 2.0을 따른다.
